# 第二章 行业背景、政策环境与市场分析

## 2.1 从合同文件管理走向合同风险运营

合同管理长期被分散在文件夹、OA 流程、电子签约、财务台账和个人经验中。电子化解决了文件传递与保存问题，却不必然解决内容理解、风险判断和跨部门协同问题。对企业而言，真正影响经营质量的不是“有多少份电子合同”，而是能否在签署前识别重大风险、在履约中跟踪关键节点、在事后快速还原审查依据与责任过程。

合同智能化因此呈现三个层次。第一层是文档数字化，将 PDF、Word 与扫描件转换为可检索文本；第二层是流程数字化，将起草、审批、签署、归档和履约组织为线上流程；第三层是风险与数据智能化，将合同条款转换为可验证风险，将金额、主体、期限和付款节点转换为结构化资产。本项目聚焦第三层，并通过标准接口连接前两层，避免重复建设电子签约或通用流程平台。

## 2.2 政策与法律环境

### 2.2.1 产业数字化提供建设方向

国务院《“十四五”数字经济发展规划》将数据资源定义为关键要素，强调数字技术与实体经济深度融合，同时要求完善数据治理体系、推进分类分级和全生命周期安全管理。[S01] 合同数据同时具有法律、财务和经营属性，是企业数据治理的重要组成。以合同为入口进行结构化抽取和风险治理，既能提升单个审查任务的效率，也能为采购、销售、资金和供应商管理提供一致的数据基础。

### 2.2.2 合同法源决定审查不能机械化

《中华人民共和国民法典》合同编系统规范合同订立、效力、履行、保全、变更转让、终止和违约责任。[S03] 最高人民法院合同编通则司法解释进一步说明，合同条款解释需要结合词句通常含义、相关条款、合同性质与目的、交易习惯、诚信原则、缔约背景和履行行为。[S04] 这意味着审查系统不能把关键词命中等同于法律结论，也不能脱离合同整体和交易事实判断条款效力。

因此，本方案采用“候选风险识别—证据检索—适用性检查—人工复核”的责任链。模型可以发现遗漏、矛盾和异常，规则可以执行金额、比例和日期等确定性校验，知识库可以提供法条与制度依据，但最终判断仍需授权人员结合事实完成。系统重点提升的是风险发现、材料组织和协同效率，而不是把法律责任交给算法。

### 2.2.3 数据与个人信息保护构成底线约束

合同可能包含自然人姓名、联系方式、身份证件、银行账户、商业价格、技术资料和印章影像。《数据安全法》要求建立数据分类分级和全流程安全管理制度，[S05]《个人信息保护法》确立合法、正当、必要、诚信、目的明确和最小范围等原则。[S06] 对合同智能审查而言，这些要求应落实为可执行设计：文件加密存储、传输加密、按部门与角色授权、敏感字段脱敏、导出水印、操作审计、备份恢复、到期删除以及模型调用数据边界。

私有化部署并不自动等于安全。若密钥与文件同库存放、管理员权限无约束、日志记录合同全文、模型缓存不可清理，数据仍可能泄露。本方案将信任边界、数据落点和责任角色纳入部署设计，以“默认不出域、按需最小暴露、全程可追踪”为原则控制风险。

### 2.2.4 生成式 AI 要求可信治理

《生成式人工智能服务管理暂行办法》提出发展与安全并重，提高生成内容准确性和可靠性，保护个人信息、知识产权、商业秘密以及用户输入与使用记录。[S02] 最高人民法院关于人工智能司法应用的意见强调安全合法、公平公正、辅助决策、透明可信和可追溯，并明确人工智能不能替代依法应由人作出的判断。[S08] 后者适用于人民法院，但其原则对法律专业场景具有重要参考价值。

中国信通院研究表明，人工智能落地正由单一模型能力转向工程化、智能体化和行业应用，需要模型、数据、算力、工具链与治理体系协同。[S09][S10] 因而，项目竞争力不应只体现为“接入大模型”，而应体现为审查任务如何分工、知识如何治理、证据如何约束、失败如何降级、结果如何验收。

## 2.3 业务痛点分析

| 痛点 | 根因 | 直接影响 | 方案响应 |
|---|---|---|---|
| 审查周期长 | 重复阅读、摘录、查法条和人工录入 | 高峰期积压，业务等待 | 批量解析、要素抽取、风险优先级排序 |
| 审查尺度不一致 | 规则分散于个人经验和多个文件 | 同类条款结论不同，难以复盘 | 版本化规则、标准模板、知识适用范围 |
| 法务财务割裂 | 审查对象和沟通工具分离 | 付款条件与履约义务的联动风险遗漏 | 双 Agent 分工、共享上下文、冲突消解 |
| 结论缺乏证据 | 模型回答或人工备注没有原文定位 | 难以信任、复核和追责 | 逐风险原文、依据、版本和处置记录 |
| 合同数据沉睡 | 字段散落在非结构化文件 | 台账滞后，管理分析依赖二次统计 | 结构化合同主数据和多维报表 |
| 规则更新困难 | 法规、制度和模板没有统一治理 | 失效依据继续被引用 | 有效期、替换链、影响分析和缓存失效 |
| 敏感信息暴露 | 公网传输、过度授权和明文存储 | 商业秘密与个人信息风险 | 本地推理、加密脱敏、最小权限和审计 |

上述问题彼此关联。例如，若只提高解析速度，却没有规则版本和证据链，审查结果仍难以复用；若只建设知识库，却没有人工反馈和更新机制，知识质量会持续衰减；若只生成报表，却没有字段证据与修正留痕，管理数据无法被信任。完整方案必须以同一合同版本和同一风险对象贯通数据、流程与责任。

## 2.4 技术机会分析

### 2.4.1 长文档解析与结构化抽取

版面分析、OCR、表格识别和大模型结构化输出，使复杂合同能够转换为带页码、段落和单元格位置的数据。正则与规则适合识别统一社会信用代码、金额格式和日期关系，大模型适合处理别名、隐含条件和跨段语义。二者结合，可以先用确定性方法产生候选，再由模型补全和归一化，最后执行类型、范围与一致性校验。

### 2.4.2 检索增强降低无依据生成

RAG 将模型回答约束在企业选择的法规、制度、模板和案例范围内。向量检索擅长语义近似，BM25 擅长法条编号、专有名词和精确词匹配，二者融合可提高不同查询类型下的稳定性。但检索命中不等于依据适用，仍需检查来源等级、适用法域、合同类型、业务维度、生效与失效日期。对无法获得可靠来源的风险，系统应降低置信度并提示人工判断，而不是用通用规则伪装为法规。

### 2.4.3 智能体协同适配跨专业任务

法务与财务关注同一合同的不同切面。法务 Agent 负责主体、效力、权利义务、违约责任、知识产权和争议解决；财务 Agent 负责金额、税率、发票、付款、结算、预算和资金风险。编排器负责上下文裁剪、顺序控制、结果去重、冲突检测和风险分档。协同价值来自专业职责、共享证据和交叉验证，而不是简单执行两次模型调用。

### 2.4.4 本地算力与可替换模型

合同数据的敏感性使本地推理和离线向量化具有现实价值。目标架构将模型能力封装为适配器，使审查编排不依赖单一供应商；在模型不可用、超时或资源紧张时，可保留解析、规则校验和人工流程，并明确标记未完成的智能环节。本地化与可替换性共同降低数据出域、供应商锁定和服务中断风险。

## 2.5 市场需求结构

本方案不使用缺乏统一口径的市场规模数字，而从采购决策关注点识别需求。不同组织对合同智能化的优先级存在差异：

| 组织类型 | 高频诉求 | 关键约束 | 优先能力 |
|---|---|---|---|
| 大型集团企业 | 多部门、多类型合同统一审查与统计 | 组织隔离、系统集成、规则统一 | 私有化、多组织权限、知识治理、报表 |
| 制造与工程企业 | 交付、验收、质保、付款联动 | 附件表格多、周期长、履约复杂 | 表格解析、节点抽取、跨条款一致性 |
| 科技与专业服务企业 | 知识产权、保密、数据与责任限制 | 非标条款多、谈判频繁 | 版本比对、风险解释、修订建议 |
| 政府与事业单位 | 采购合规、审计留痕、数据安全 | 权限严格、流程规范、可追溯 | 本地部署、审计、规则依据、报表 |
| 中型企业 | 快速获得标准化审查能力 | 实施资源有限、易用性要求高 | 模板化配置、轻量部署、清晰工作流 |

由此可见，市场不是单一“AI 审合同”需求，而是专业审查、流程协同、数据治理、安全部署和系统集成的组合需求。产品路线应以可配置能力覆盖差异，而非为每个行业复制一套不可维护的系统。

## 2.6 竞品与替代方案分析

公开市场大致存在三类方案：电子签约与合同管理一体化平台、专业合同审查产品、通用 AI 文档处理平台。e签宝公开展示合同风险审查以及合同管理与签署相关能力，[S11] 法大大公开展示模板、协作编辑、起草、审查、签署和归档等流程能力，[S12] 百度 AI 开放平台公开展示要素抽取、风险审查、版本比对、归档、API 和私有化部署。[S13] 下表只比较官方页面明确说明的维度；“公开资料未说明”不表示产品不具备该能力。

| 能力维度 | e签宝 | 法大大 iContract | 百度合同智能处理 | 契鉴目标方案 |
|---|---|---|---|---|
| 合同接入与管理 | 官方页面说明 | 官方页面说明 | 官方页面说明 | 多格式、批量、版本与失败隔离 |
| 风险审查与定位 | 官方页面说明 | 官方页面说明 | 官方页面说明 | 逐风险原文、依据、置信度与状态 |
| 知识版本治理 | 公开资料未说明 | 公开资料未说明 | 公开资料未说明 | 分类、有效期、替换链与适用性过滤 |
| 法务财务协同 | 公开资料未说明 | 公开资料未说明 | 公开资料未说明 | 专业双 Agent、交叉验证与冲突消解 |
| 人工复核闭环 | 公开资料未说明 | 公开资料未说明 | 公开资料未说明 | 确认、忽略、整改、再审、关闭与留痕 |
| 多维经营分析 | 公开资料未说明 | 公开资料未说明 | 归档检索有说明 | 合同、金额、相对方、节点与风险分析 |
| 私有化与模型替换 | 公开资料未说明 | 公开资料未说明 | 私有化及自定义模型有说明 | 全链路私有化、模型适配与离线 Embedding |
| 审计与责任边界 | 公开资料未说明 | 公开资料未说明 | 公开资料未说明 | 知识、模型、操作和导出全程追踪 |

契鉴不以替代电子签约平台为目标，而是形成可嵌入 OA、合同管理或电子签约流程的“审查与风险数据中枢”。差异化集中在五点：法务与财务协同、逐风险证据链、知识版本治理、人机责任闭环、多维经营数据治理。该定位既避免与成熟签署基础设施正面重复，也使核心能力能够通过 API 和私有化部署服务不同业务系统。

## 2.7 行业进入判断

行业机会成立的前提是同时满足专业可信与工程可用。只有模型效果而没有流程、安全和审计，难以进入企业核心合同场景；只有流程与归档而没有条款理解和证据组织，又无法显著降低专业人员负担。本方案选择“高价值辅助、关键节点人工负责”的进入路径：先覆盖标准合同与高频风险，建立可度量的审查闭环；再通过知识治理和企业配置扩大适用范围；最后连接 OA、ERP 与电子签约平台，形成合同数据驱动的风险运营能力。

该路径的判断标准不是宣传性的“完全替代人工”，而是三个可验收结果：重复劳动是否减少，高风险是否更早暴露，结论是否更容易复核和追踪。三者同时成立，合同智能化才具备持续推广价值。
