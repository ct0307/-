# 企业级合同合规审查与多维报表生成智能体系

## 产品需求分析文档（PRD）

**赛题编号：** A03  
**命题单位：** 海康-南湖研究院  
**命题方向：** 政企服务 / 人工智能  
**文档版本：** V1.0  
**编制日期：** 2026年7月15日  
**文档定位：** 比赛评审与研发实施双用途  
**产品口径：** 赛题理想目标方案

> 核心结论：本产品不是单一的“合同问答工具”，而是一套覆盖合同接入、智能解析、双 Agent 协同审查、人工复核、整改闭环和管理报表的企业级合同合规作业系统。产品以 OpenClaw 一体机为本地智能算力底座，以可解释审查和结构化数据沉淀为核心价值，在确保合同数据不出域的前提下，提高审查效率、降低漏审风险，并将合同信息转化为可持续使用的经营决策资产。

## 1. 文档概述

### 1.1 编写目的

本文档用于统一比赛评审、产品设计、研发实现、测试验收和演示答辩对目标产品的理解，重点回答以下问题：

- 合同要素抽取准确率、批量处理和算力对比如何量化验收；
- 双 Agent、RAG 知识库、人工复核和多维报表如何协同工作；
- 产品从比赛版本演进到企业生产版本需要满足哪些安全与治理要求。

### 1.2 需求来源

需求主要来自以下四类输入：

1. A03 赛题背景、任务要求和技术指标；

4. 企业级 AI 应用在可解释性、隐私保护、稳定性和可审计性方面的通用要求。

### 1.3 文档范围

本文描述目标产品的理想形态，不受当前原型实现范围限制。需求优先级定义如下：

### 1.4 术语说明

| 术语 | 说明 |

## 2. 赛题解读与产品机会

### 2.1 赛题核心要求

赛题要求可以归纳为四项核心能力和三项硬指标。

**核心能力：**

1. 对 PDF、Word 合同进行类脑加速解析；
2. 识别合同漏洞、逻辑矛盾及违反《中华人民共和国民法典》等法律规范的条款，并给出修改建议；
3. 提取甲乙方、合同标的、收付款节点等关键元数据，生成 Excel 和可视化报表；
4. 构建“法务专家 Agent + 财务会计 Agent”的协同审查体系。

**硬指标：**

- 合同关键要素抽取准确率不低于 90%；
- 一次性批量上传并处理 50 份以上合同；
- OpenClaw 一体机方案在核心性能指标上显著优于传统 GPU 对照方案。

### 2.2 业务痛点

| 痛点 | 现状表现 | 业务后果 |
|---|---|---|
| 审查效率低 | 法务逐页阅读、复制条款、人工查法条 | 审查周期长，高峰期形成积压 |
| 审查质量依赖个人 | 不同人员经验、关注点和尺度不一致 | 风险漏审、建议不统一、难以复盘 |
| 法务财务割裂 | 合规条款与付款、税务、结算分别审查 | 条款联动风险难以及时发现 |
| 合同数据不可用 | 关键信息散落在 PDF、Word 正文 | 台账更新滞后，管理者看不到实时数据 |
| 审查缺乏证据链 | AI 或人工结论没有明确原文和依据 | 结果难以信任，责任难以追溯 |
| 数据安全压力大 | 合同包含商业秘密和个人信息 | 公网模型调用带来泄露与合规风险 |

### 2.3 产品机会

产品应将“文档处理工具”升级为“合同风险运营平台”：前端以合同审查任务为入口，中台将文档转化为结构化合同资产，智能层通过双 Agent 和知识库输出可解释风险，管理层通过报表获得实时经营洞察，最终形成可追踪、可复核、可持续优化的闭环。

## 3. 产品定位与目标

### 3.1 产品定位

面向大型企业和政府单位的本地化合同合规智能作业平台，为法务、财务、业务和管理者提供“读懂合同、识别风险、协同复核、推动整改、汇总决策”的一体化能力。

### 3.2 产品价值主张

- **更快：** 批量处理合同，减少重复阅读、摘录和台账维护工作；
- **更准：** 通过规则、RAG 和多 Agent 交叉验证降低漏审与误报；
- **更可信：** 每项风险均提供原文定位、法规依据、置信度和处理记录；
- **更协同：** 法务、财务和业务在同一风险对象上分工处理；
- **更安全：** 合同解析、推理和存储在企业本地环境完成；
- **更可决策：** 将合同文本转化为可筛选、统计和导出的结构化数据。

### 3.3 产品目标

| 目标编号 | 产品目标 | 衡量指标 |
|---|---|---|
| G1 | 提升合同审查效率 | 单份标准合同从上传到首轮结果的 P95 时长满足设定 SLA |
| G2 | 保证关键要素质量 | 标准测试集字段级准确率 ≥90%，核心字段召回率 ≥95% |
| G3 | 降低高风险漏审 | 高风险条款召回率 ≥90%，所有红档结果必须可解释 |
| G4 | 支撑批量作业 | 单批次至少 50 份，单文件失败不影响其他文件 |
| G5 | 实现人机协同闭环 | AI 风险均可复核，需修改项可进入整改并追踪关闭 |
| G6 | 形成管理数据资产 | 合同元数据、风险和履约节点可查询、统计、导出 |
| G7 | 证明本地算力价值 | OpenClaw 单份总耗时 P95 较 GPU 降低 ≥20%，批量吞吐提升 ≥20%，质量下降 ≤2 个百分点 |

### 3.4 非目标

- 不替代律师或企业法务作出最终法律判断；
- 不直接代替电子签章、印章审批和财务付款系统；
- 不在未经授权的情况下自动修改并签署合同；
- 不承诺覆盖全部法域，首期以中国大陆现行法律法规和企业内部制度为主；
- 不将模型生成内容作为唯一证据，所有结论必须允许人工复核。

### 3.5 产品设计原则

1. 结论先行，证据随手可查；
2. AI 提建议，人对决策负责；
3. 一次录入，多处复用；
4. 单点失败不阻断批量任务；
5. 权限最小化，敏感数据默认保护；
6. 指标可测量，结果可复现，过程可审计。

## 4. 用户角色与核心场景

### 4.1 用户角色

| 角色 | 核心诉求 | 主要权限 |
|---|---|---|
| 业务经办人 | 快速提交合同、查看问题、完成整改 | 上传本部门合同、查看脱敏结果、处理分配给自己的整改 |
| 法务人员 | 高效定位合规风险并统一审查尺度 | 审查全部授权合同、复核风险、维护法律规则和建议 |
| 财务人员 | 核对金额、付款、税务和结算风险 | 查看财务相关字段、复核财务风险、导出台账 |
| 法务/财务主管 | 管理审查队列、质量和超期事项 | 分派任务、查看部门统计、审批重大风险 |
| 管理层 | 快速掌握合同规模、金额、风险与履约情况 | 查看聚合报表和关键风险，不默认访问敏感原文 |
| 系统管理员 | 维护组织、权限、模型与系统配置 | 用户角色、字典、模型、知识库、审计日志与运行监控 |
| 审计人员 | 核验系统操作和风险处置过程 | 只读访问授权范围内的操作日志、版本和导出记录 |

### 4.2 核心用户故事

- 作为业务经办人，我希望一次上传多份合同并自动获得错误提示，避免逐份录入；
- 作为法务人员，我希望优先查看高风险条款，并能直接看到原文、依据和修改建议；
- 作为财务人员，我希望系统自动提取金额、付款条件和发票要求，发现不一致或缺失；
- 作为主管，我希望知道哪些合同待复核、哪些整改逾期以及高风险集中在哪些部门；
- 作为管理者，我希望按合同类型、金额、相对方和时间查看报表并导出 Excel；
- 作为管理员，我希望所有模型调用、知识来源和人员操作均可追踪。

### 4.3 典型业务场景

**场景 A：单份合同快速审查。** 业务人员上传采购合同，系统解析后由法务和财务 Agent 协同审查，法务复核红档风险并生成整改建议。

**场景 B：月末批量审查。** 部门一次上传 50 份以上合同，系统形成任务队列并行处理，失败文件可单独重试，主管查看整体进度和异常。

**场景 C：历史合同盘点。** 管理层希望了解年度合同金额、主要相对方、付款节点和风险分布，系统从结构化数据生成看板和 Excel 台账。

**场景 D：规则更新影响分析。** 法规或内部制度更新后，管理员更新知识库并标记生效日期，系统对相关合同提示重新审查范围。

## 5. 产品范围与系统边界

### 5.1 产品范围

产品由八个业务域组成：

1. 合同接入与任务管理；
2. 文档解析与要素抽取；
3. 智能审查与风险解释；
4. 双 Agent 协同与冲突消解；
5. 人工复核与整改闭环；
6. 多维报表与 Excel 导出；
7. 法规知识库与规则模板；
8. 权限、安全、审计与系统管理。

### 5.2 外部系统边界

| 外部系统 | 集成目的 | 首期策略 |
|---|---|---|
| OA/BPM | 接收审批单和回写审查结果 | P2 提供标准 REST API 与回调 |
| 电子签章 | 审查通过后进入签署流程 | P3 仅传递合同 ID 与版本，不直接操作印章 |
| 财务/ERP | 同步供应商、付款和台账信息 | P3 通过主数据编码关联 |
| 统一身份认证 | 单点登录和组织同步 | P2 支持 OIDC/SAML/LDAP |
| 消息平台 | 超期、完成和重大风险提醒 | P2 支持企业微信/钉钉/邮件适配器 |

### 5.3 产品边界约束

- 合同原文、附件、向量与审查结果默认不出企业安全域；
- 外部系统只能访问经授权的结构化结果，不直接获得全量原文；
- 每次审查绑定合同版本、规则版本、知识库版本和模型版本；
- 已签署合同不得覆盖原文件，只能创建新版本或补充协议关联。

## 6. 核心业务流程

### 6.1 主流程

1. 用户选择合同类型、所属部门和审查维度，上传一份或多份文件；
2. 系统执行格式、大小、病毒、重复和权限校验；
3. 文件加密落盘，建立合同记录和批次任务；
4. 解析服务提取正文、表格、页码、段落和附件关系；
5. 要素服务抽取甲乙方、金额、期限、标的、付款节点等字段，并给出字段置信度；
6. 规则引擎执行确定性校验，RAG 检索适用法规、制度和标准条款；
7. 法务专家 Agent 与财务会计 Agent 分工审查并共享必要上下文；
8. 协同引擎合并重复问题、识别跨域冲突并确定风险等级；
9. 用户查看审查摘要，逐项完成人工复核；
10. “需修改”风险自动形成整改任务，完成后进入复核关闭；
11. 结构化合同数据和风险状态进入报表、台账和管理看板。

### 6.2 合同处理状态

| 状态 | 进入条件 | 可执行操作 | 退出条件 |
|---|---|---|---|
| 待解析 | 文件上传并通过基础校验 | 取消、查看队列 | 开始解析 |
| 解析中 | 解析任务已领取 | 查看进度 | 解析成功或失败 |
| 待审查 | 正文与关键要素已生成 | 发起审查、修正元数据 | 审查任务启动 |
| 审查中 | 至少一个 Agent 正在运行 | 查看阶段进度 | 双 Agent 汇总完成或失败 |
| 待复核 | 已形成风险清单 | 复核、追问、分派 | 所有必审风险完成处理 |
| 整改中 | 存在“需修改”风险 | 更新方案、上传新版本 | 整改复核完成 |
| 已完成 | 审查和必要整改均闭环 | 导出、归档、重新审查 | 创建新版本时转入新流程 |
| 失败 | 解析或审查不可恢复失败 | 查看原因、单独重试 | 重试成功或人工终止 |

### 6.3 风险复核状态

风险条目初始为“待复核”。法务或财务可将其更新为“已确认”“已忽略”或“需修改”；“需修改”生成整改任务，整改经复核后变为“已关闭”。忽略高风险必须填写原因，关闭风险必须保留处理证据。

### 6.4 异常处理原则

- 单文件失败不影响同批次其他文件；
- 同一文件支持幂等重试，不重复创建合同记录；
- OCR、解析或模型超时应标记具体阶段并支持从失败阶段续跑；
- 模型不可用时允许规则审查继续，但必须明确标记“AI 审查未完成”；
- 导出失败不影响审查结果，用户可在导出中心重新生成；
- 所有系统异常不得向普通用户暴露密钥、路径或内部堆栈。

## 7. 功能需求

### 7.1 身份认证与工作台

#### FR-01 登录与身份认证（P1）

**需求描述：** P1 支持账号密码登录、退出、会话续期和连续失败保护；企业统一身份认证属于 P2 集成能力，不作为比赛闭环版的前置依赖。

**业务规则：**

- 登录成功后根据角色和部门加载可访问模块；
- 连续 5 次失败后锁定 15 分钟或触发验证码；
- 管理员可强制失效指定用户会话；
- 密码、令牌和敏感配置不得写入业务日志。

**验收标准：** 正确账号可进入授权首页；错误密码不泄露账号是否存在；越权路由和接口均返回拒绝；退出后旧令牌不可继续使用。

#### FR-02 角色化工作台（P1）

**需求描述：** 根据角色展示待办、近期审查、整改超期、风险趋势和快捷入口。

**业务规则：** 法务优先展示待复核高风险；财务优先展示付款与结算风险；业务人员仅看到本人或本部门事项；管理层默认查看聚合数据。

**验收标准：** 工作台数据来自真实业务对象；卡片可钻取对应列表；无数据时提供清晰空状态，不显示伪造演示数据。

### 7.2 合同接入与任务管理

#### FR-03 单份与批量上传（P1）

**需求描述：** 支持点击、拖拽、文件夹拖入等方式上传 PDF、DOC、DOCX 文件，单批至少支持 50 份，目标支持 200 份。

**业务规则：**

- 每个文件显示等待、上传、解析、审查、完成或失败状态；
- 校验扩展名、MIME、大小、加密文件、损坏文件和空文件；
- 支持同名覆盖、新版本和跳过三种重复处理策略；
- 批次提交后允许关闭窗口，任务在后台继续；
- 失败文件提供原因、重试和移除操作。

**验收标准：** 固定批次包含 50 份有效合同、总页数不少于 500 页，其中 PDF 与 DOCX 均不少于 20 份、扫描件不少于 10 份，单份 5—30 页；在冻结硬件上 30 分钟内完成处理，有效文件成功率不低于 98%。另加入 2 份损坏或加密异常文件验证失败隔离；刷新页面后可恢复进度，重复提交不会产生无关联记录。

#### FR-04 合同基本信息（P1）

**需求描述：** 上传时记录合同名称、类型、部门、经办人、审查维度和优先级，系统自动生成合同编号。

**业务规则：** 合同类型和部门来自管理员字典；必填项缺失时禁止提交；系统识别结果可在权限范围内人工修正并保留修改轨迹；P1 必须具备基础版本关联，新文件可标记为原合同的新修订稿，完整差异识别和增量审查属于 FR-05 的 P2 范围。

**验收标准：** 合同信息可检索、筛选、排序和导出；手工修改显示修改人、时间和前后值。

#### FR-05 高级版本差异与附件管理（P2）

**需求描述：** 维护草案、修订稿、定稿、补充协议及附件之间的关联，支持版本差异对比。

**验收标准：** 用户可查看版本链；已签署版本不可覆盖；差异页能定位新增、删除和修改条款；重新审查仅处理受影响内容并保留历史结论。

### 7.3 文档解析与要素抽取

#### FR-06 文档解析（P1）

**需求描述：** 解析 PDF、Word 正文、表格、页眉页脚和段落层级；扫描 PDF 自动进入 OCR。

**业务规则：**

- 保存文本与页码、段落、表格单元格的映射；
- 清理重复页眉页脚、乱码碎片和无意义空白；
- OCR 结果低于质量阈值时提示人工核对；
- 不将解析失败误报为“未发现风险”。

**验收标准：** 原生 PDF、DOCX 正文字符覆盖率不低于 98%，表格关键单元格保留率不低于 95%；300 DPI 清晰扫描件 OCR 字符准确率不低于 95%；原文页码或段落定位准确率不低于 95%。解析失败须准确区分密码保护、文件损坏和空白扫描。“类脑加速”不作为模糊功能名称单独验收，而由上述解析质量与第 8.4 节 OpenClaw 延迟、吞吐指标共同证明。

#### FR-07 关键要素抽取（P1）

**需求描述：** 自动提取合同编号、名称、类型、甲乙方、统一社会信用代码、合同标的、金额、币种、税率、签订日期、生效日期、履行期限、付款节点、发票要求、交付地点、验收条件、违约责任、争议解决、联系人等字段。

**业务规则：**

- 每个字段保留值、原文证据、位置和置信度；
- 金额同时保留原文和标准化数值，大小写金额不一致时产生风险；
- 多个付款节点按顺序结构化为比例、金额、触发条件和期限；
- 低置信度或多个候选值进入人工确认队列；
- 字段修正应回流为评测与优化样本，但不得自动污染正式规则。

**验收标准：** 按第 12.3 节冻结测试集与宏平均口径验收，总体关键要素得分不低于 90%；甲乙方、金额、期限、付款节点等核心字段召回率不低于 95%，任一核心字段得分不低于 85%；每个非空字段均可查看证据。

#### FR-08 要素一致性校验（P1）

**需求描述：** 校验正文与附件、数字与大写金额、分项与合计、付款比例、日期先后、主体名称等一致性。

**验收标准：** 金额不一致、付款比例不等于 100%、履行截止早于生效日期等预置样本均被识别，并给出可理解的差异说明。

### 7.4 智能审查与风险解释

#### FR-09 审查维度配置（P1）

系统至少提供主体资格、合同效力、权利义务、价款支付、履约验收、违约责任、知识产权、保密与数据、解除终止、争议解决、财税合规和格式完整性等维度。用户可按合同类型启用推荐组合，管理员可配置企业模板。

#### FR-10 风险识别（P1）

**需求描述：** 识别缺失条款、逻辑矛盾、权责失衡、表述歧义、履约风险、财务风险以及违反法律法规或内部制度的内容。

**风险条目必须包含：**

- 风险标题与分类；
- 风险等级（红/黄/绿或高/中/低）；
- 合同原文及页码/段落；
- 问题说明和可能后果；
- 法规、制度或标准条款依据；
- 可直接使用的修改建议；
- 置信度、识别来源和负责角色；
- 人工复核与整改状态。

**验收标准：** 按第 12.4 节冻结集验收，高风险召回率不低于 90%、整体 F1 不低于 85%、伪造法规引用为 0、可验证依据率不低于 98%；风险不得只有结论没有原文，建议不得改变合同核心商业意图而不提示用户。

#### FR-11 风险分级（P1）

**业务规则：**

- 高风险：可能导致合同无效、重大损失、监管处罚或核心权利无法实现；
- 中风险：可能造成履约争议、成本增加或管理困难；
- 低风险：规范性、完整性或可读性问题；
- 风险等级由规则严重度、金额影响、发生概率、证据强度和企业偏好共同决定；
- 高风险不得因模型低置信度自动隐藏，应进入重点复核队列。

#### FR-12 修改建议与条款替换（P1）

**需求描述：** 对风险生成修改原则和可复制的建议条款，支持“原文—建议—依据”对照。

**验收标准：** 按第 12.4 节不少于 100 条建议进行双专家评审，五分制平均分不低于 4.0、4 分及以上占比不低于 85%、严重错误为 0；涉及金额、期限、主体等信息时使用明确占位提示，不擅自编造，应用前必须确认并留痕。

#### FR-13 风险追问（P2）

用户可围绕单条风险追问行业惯例、谈判空间和修改原因。对话始终绑定当前合同与风险上下文，回答需引用已授权知识来源；切换风险后上下文隔离，禁止跨合同泄露。

### 7.5 双 Agent 协同

#### FR-14 法务专家 Agent（P1）

重点审查主体资格、合同效力、权利义务、违约责任、解除终止、知识产权、保密、数据合规和争议解决，输出法务风险与法规依据。

#### FR-15 财务会计 Agent（P1）

重点审查合同金额、币种、税率、发票、付款节点、结算条件、保证金、违约金计算、预算科目和台账完整性，输出财务风险与结构化台账字段。

#### FR-16 协同编排（P1）

**需求描述：** 法务 Agent 先识别合同法律结构和关键义务，财务 Agent 在共享必要上下文后检查金额与履约条件，协同引擎合并结果。

**业务规则：**

- 两个 Agent 独立保留原始输出，便于追溯；
- 相同风险去重合并，不简单重复展示；
- 当法务结论与财务结论冲突时，生成“待人工裁决”事项；
- 跨域风险必须同时展示双方观点，例如付款条件与验收义务不匹配；
- 任一 Agent 失败时展示部分结果和失败状态，允许单独重跑。

**冲突裁决规则：** 跨域冲突由法务主管担任案件协调人，法律效力和合规结论由法务主管确认，金额、税务和账务事实由财务主管确认；风险等级或处置建议不一致时必须由双方主管共同确认。双方仍无法达成一致时，升级至组织指定的合同审批负责人或评审委员会，裁决前不得发布正式审查报告。

**报告纳入规则：** 草稿报告可以展示全部风险，但必须标明待复核、低置信度或无可靠依据状态；正式报告仅将“已确认”“需修改”“已关闭”风险计入正式结论，“已忽略”风险进入审计附录且不计入当前风险数。存在待复核高风险、任何低置信度结果或任何无可靠依据结果时，一律阻断正式报告发布；只有证据充分、置信度正常的中低风险未决项可列入“待确认事项”，不计入正式结论，并由报告签发人确认。

**验收标准：** 构造金额、付款和违约责任联动样本，系统能输出跨域风险；冲突结果不得被静默覆盖；可查看每项风险由哪个 Agent、规则或知识来源产生。模拟双方主管意见不一致时，事项能升级至指定负责人，且未决高风险无法发布正式报告。

#### FR-17 性能调度（P2）

系统根据文件长度、批次规模和任务优先级调度 OpenClaw 算力；交互任务优先，批量任务限流；支持并发度、超时、重试和熔断配置。

### 7.6 人工复核与整改闭环

#### FR-18 风险复核（P1）

**需求描述：** 授权人员可确认、忽略或要求修改风险，支持批量操作和复核备注。

**业务规则：** 高风险忽略必须填写原因；财务风险默认由财务复核，法律风险默认由法务复核；跨域风险须至少一方主管确认；复核操作不可物理删除。

**验收标准：** 状态更新后工作台与报表同步变化；重复提交保持幂等；越权用户无法修改状态。

#### FR-19 整改任务（P1）

“需修改”风险自动生成整改项，包含责任人、截止时间、整改建议、关联合同版本和证据。P1 支持待处理、处理中、待复核、已关闭、重新打开状态，并在站内待办中标记逾期和升级层级；企业微信、钉钉、邮件等外部消息提醒属于 FR-33 的 P2 范围。

#### FR-20 审查报告（P1）

支持生成审查摘要，内容包括合同基本信息、总体风险等级、风险数量、核心结论、逐条风险、复核状态和免责声明。报告导出需带合同版本、生成时间、规则版本和模型版本。

### 7.7 多维报表与台账

#### FR-21 合同台账（P1）

**需求描述：** 以结构化表格展示合同名称、编号、类型、甲乙方、标的、金额、币种、签订日期、履行期限、付款节点、部门、经办人、风险等级和状态。

**验收标准：** 支持字段筛选、组合查询、排序、分页、列配置和权限过滤；显示值与合同详情一致；低置信度字段有明显标识。

#### FR-22 可视化报表（P1）

至少提供：合同数量与金额趋势、合同类型分布、部门分布、风险等级分布、风险类别排行、主要相对方、付款节点日历、到期提醒、整改状态和平均审查耗时。

**业务规则：** 图表支持时间、部门、合同类型和金额区间联动筛选；指标必须显示口径说明；管理层聚合数据默认脱敏。

#### FR-23 Excel 导出（P1）

**需求描述：** 导出合同台账、风险台账和履约节点表，字段顺序可配置。

**业务规则：** 导出遵循当前筛选条件和数据权限；敏感字段按角色脱敏；大批量导出异步生成；导出行为记录在审计日志。

**验收标准：** 文件可被 Excel 正常打开；表头、日期、金额和多行文本格式正确；导出记录数与筛选结果一致；无权限数据不出现在文件中。

#### FR-24 管理驾驶舱（P2）

突出重大合同、高风险合同、即将到期节点、逾期整改和部门风险趋势，支持从聚合指标下钻至授权合同清单。

### 7.8 知识库、规则与模板

#### FR-25 法规知识库（P1）

**需求描述：** 管理法律法规、司法解释、行业规范、企业制度、标准条款和典型案例，支持 TXT、PDF、Word 批量导入。

**业务规则：**

- 法规优先按章、条切片，模板按条款层级切片；
- 每个知识片段记录来源、版本、生效日期、失效日期和适用范围；
- 自动过滤碎片、占位符和空内容；
- 导入前检测同一法规或条文重叠，支持覆盖、并存或取消；
- 失效知识默认不参与新审查，但历史报告仍可追溯。

**验收标准：** 检索结果可定位原始来源；重复导入有明确预警；失效版本不污染当前答案；知识条目删除和覆盖受管理员权限控制。

#### FR-26 混合检索与引用（P1）

采用关键词检索与向量检索融合，根据合同类型、审查维度、生效时间和适用范围过滤。每项引用展示来源名称、条文编号、内容摘要和匹配度；当没有可靠依据时明确提示，不伪造条文。

#### FR-27 审查规则（P2）

管理员可维护规则名称、适用合同类型、审查维度、严重度、触发条件、建议和启停状态。内置规则不可直接删除，只能停用或复制为自定义规则；规则变更需版本化。

#### FR-28 合同模板（P2）

支持维护标准合同模板、推荐条款和禁用条款；审查时可对比模板差异，并将企业标准条款作为优先建议来源。

### 7.9 系统管理与审计

#### FR-29 组织、用户与权限（P1）

支持组织、部门、岗位、用户、角色和数据范围配置。权限同时控制菜单、接口、字段和数据行；管理员授权不得突破自身管理范围。

#### FR-30 基础字典（P1）

管理员维护合同类型、业务部门、审查维度、风险分类、通知方式等字典。被历史数据引用的字典值只能停用，不可直接删除。

#### FR-31 审计日志（P1）

记录登录、上传、查看敏感合同、下载、审查、复核、整改、导出、知识库和权限变更。日志至少包含人员、时间、IP、对象、动作、结果和必要的前后值；普通管理员不可修改日志。

#### FR-32 模型与调用管理（P2）

展示模型供应方、版本、调用 Agent、耗时、令牌量、成功率和失败原因；支持配置超时、并发、降级和启停，不在日志中记录完整敏感提示词。

#### FR-33 系统通知（P2）

在 P1 站内待办和状态标记基础上，P2 对批次完成、解析失败、高风险待复核、整改逾期、合同到期和知识版本失效发送主动通知，并按配置扩展至企业微信、钉钉或邮件等平台。

## 8. 智能能力设计要求

### 8.1 智能审查策略

系统采用“确定性规则 + RAG + 大模型 + 人工复核”的组合方案：规则负责金额、日期、字段缺失等可明确计算的问题；RAG 提供有效知识依据；大模型理解语义、权责关系和跨条款逻辑；人工对高风险与低置信度结论作最终判断。

### 8.2 输出结构约束

模型输出必须符合固定结构，至少包含风险分类、等级、原文、问题说明、依据、建议、置信度和责任 Agent。解析失败时不得将自由文本直接写入正式风险表，应进入异常队列或重新请求。

### 8.3 可信度控制

- 法规引用必须来自检索结果，不允许模型自行编造条文编号；
- 低于置信度阈值的结果进入人工确认，不计入自动通过；
- 同一风险由规则和模型同时命中时提升证据强度，但不机械提高严重度；
- 记录模型、提示词模板、知识库和规则版本以支持复现；
- 建立“误报、漏报、建议不可用”反馈标签，形成持续评测集。

### 8.4 性能对比方案

OpenClaw 与传统 GPU 对照测试必须使用同一合同集、模型或等效模型、提示词、并发和输出要求，至少比较：

| 指标 | 定义 | 统计方式 |
|---|---|---|
| 首结果延迟 | 提交到首条有效审查结果的时间 | P50、P95 |
| 单份总耗时 | 提交到完整结果的时间 | P50、P95 |
| 批量吞吐 | 单位时间完成的合同数或页数 | 固定 50 份测试集 |
| 成功率 | 无人工干预完成的任务比例 | 成功数/总任务数 |
| 资源占用 | CPU、内存、显存/专用算力占用 | 峰值与均值 |
| 能耗/成本 | 完成固定工作量的能耗或成本 | 同口径估算 |

**冻结基线：** 比赛前固定 GPU 型号、显存、功耗上限、驱动/CUDA、推理框架、模型文件哈希、精度/量化方式、上下文长度和并发配置。OpenClaw 与 GPU 必须使用同一模型、提示词和输出结构；“等效模型”仅可作为补充实验，不得用于核心优越性结论。测试集、预热次数和统计脚本同步冻结。

**重复与统计：** 每个平台先预热 3 轮，再对固定 50 份合同连续测试 5 轮，报告均值、P50、P95、标准差和 95% 置信区间，并保留每轮原始日志。不得在测试完成后选择对自身有利的指标。

**强制通过阈值：** 两项主指标预先固定为“单份总耗时 P95”和“批量吞吐”。OpenClaw 的 P95 总耗时必须较 GPU 降低至少 20%，批量吞吐必须提升至少 20%；同时有效任务成功率不低于 98%，关键要素质量相对下降不超过 2 个百分点。

## 9. 数据需求

### 9.1 核心数据实体

| 实体 | 关键字段 | 说明 |
|---|---|---|
| 用户与组织 | 用户、角色、部门、数据范围 | 权限与责任归属基础 |
| 合同 | 编号、类型、主体、金额、期限、状态 | 产品核心业务对象 |
| 合同文件/版本 | 文件、哈希、版本、加密标识 | 原始证据与版本链 |
| 解析片段 | 页码、段落、表格、坐标、文本 | 原文定位基础 |
| 关键要素 | 字段、值、证据、置信度 | 台账和报表基础 |
| 风险条目 | 分类、等级、原文、依据、建议、状态 | 审查与闭环基础 |
| 整改任务 | 责任人、截止时间、证据、状态 | 风险处置基础 |
| 知识条目 | 来源、条文、版本、有效期、向量 | RAG 检索基础 |
| 规则与模板 | 条件、适用范围、版本、状态 | 企业审查标准 |
| 审计与调用日志 | 人员、动作、对象、耗时、结果 | 合规追溯与运维 |

### 9.2 数据质量规则

- 合同编号在组织范围内唯一；
- 文件通过哈希识别重复，版本关系不得形成环；
- 金额字段保留原始文本、数值和币种；
- 所有风险必须关联合同版本和原文片段；
- 知识条目必须有来源和版本，无法确认来源的内容不得进入正式库；
- 删除采用逻辑删除或归档，审计记录不可随业务对象删除。

### 9.3 数据生命周期

合同原文、审查结果和操作日志的保留期限由组织策略配置。到期后按“归档—复核—销毁”流程处理；涉及争议、诉讼或审计冻结的数据不得销毁。测试环境原则上使用脱敏或合成数据。

## 10. 权限、安全与合规要求

### 10.1 权限模型

采用 RBAC 与部门数据范围结合的权限模型，并增加字段级控制。法务可在授权范围查看完整原文；业务人员默认仅查看本部门合同且敏感字段脱敏；管理层默认查看聚合结果，需要查看原文时进行二次授权。

### 10.2 数据安全

- 传输采用 TLS，存储采用企业认可的加密算法；
- 文件密钥与业务数据库分离管理并支持轮换；
- 合同、向量、模型缓存和备份均纳入敏感数据管理；
- 导出文件包含水印、导出人和时间，可配置有效期；
- 日志进行脱敏，不记录完整合同内容、密码、令牌和密钥；
- 支持备份恢复、数据销毁证明和安全事件追踪。

### 10.3 本地化与模型安全

生产环境的解析、Embedding、推理和向量检索全部在企业内网完成。模型或知识库升级必须经过离线评测和审批；禁止未经授权将合同片段发送至公网接口。

### 10.4 AI 使用声明

界面和报告中应明确“AI 结果用于辅助审查，不构成最终法律意见”。待复核高风险、任何低置信度结果和任何无可靠依据结果必须先完成人工复核，否则系统不得发布正式审查报告；证据充分、置信度正常的中低风险未决项仅可进入“待确认事项”，不得计入正式结论。

## 11. 非功能需求

### 11.1 性能

| 编号 | 指标 | 目标 |
|---|---|---|
| NFR-P01 | 批量能力 | 单批 ≥50 份，目标 200 份 |
| NFR-P02 | 页面响应 | 常用查询 P95 ≤2 秒（不含大模型任务） |
| NFR-P03 | 上传反馈 | 选择文件后 1 秒内显示队列与状态 |
| NFR-P04 | 审查进度 | 长任务至少按解析、抽取、法务、财务、汇总五阶段反馈 |
| NFR-P05 | 导出能力 | 1 万行以内同步或短时异步完成，超量任务进入导出中心 |

### 11.2 可用性与可靠性

- 核心业务月度可用性目标不低于 99.5%；
- 任务状态持久化，服务重启后可继续或安全重试；
- 接口和任务具备幂等标识；
- 数据库、文件、知识库和配置具备一致的备份恢复方案；
- 单个模型、Agent 或文档失败时不扩大为系统级故障。

### 11.3 兼容性

支持近三年主流 Chrome、Edge 浏览器；支持常见 PDF、DOC、DOCX；Excel 导出兼容 Office 2019 及以上；界面在 1366×768、1920×1080 和常见窄屏下保持可操作。

### 11.4 易用性与无障碍

- 新用户无需培训即可完成“上传—审查—复核—导出”主流程；
- 重要状态同时使用文字、图标和颜色表达；
- 错误提示说明原因和下一步，不只显示错误码；
- 表单支持键盘操作、焦点状态和必要的辅助说明；
- 批量队列、空状态、错误状态和弱网状态均有明确反馈。

### 11.5 可维护性与可观测性

- 模型、规则、知识和合同解析器可独立升级；
- 关键链路记录请求 ID、批次 ID 和合同 ID；
- 监控任务积压、解析失败率、模型成功率、P95 延迟和资源使用；
- 告警分为业务告警、性能告警和安全告警，并配置责任人。

## 12. 指标体系与评测方案

### 12.1 北极星指标

**有效审查闭环合同数：** 在统计周期内完成智能审查、必要人工复核并形成可追溯结果的合同数量。该指标同时反映使用规模、结果可用性和闭环能力。

### 12.2 产品指标

| 指标类别 | 指标示例 | 目的 |
|---|---|---|
| 效率 | 单份审查耗时、批量吞吐、人工处理时长 | 证明效率提升 |
| 质量 | 字段准确率、风险召回率、误报率、建议采纳率 | 证明结果有效 |
| 闭环 | 待复核率、整改完成率、平均关闭时长 | 证明可执行性 |
| 使用 | 活跃用户、上传量、导出量、模块使用率 | 发现真实价值 |
| 稳定 | 成功率、失败率、重试率、P95 延迟 | 保障可用性 |
| 安全 | 越权拦截、敏感导出、异常登录、安全告警 | 保障合规性 |

### 12.3 要素准确率评测

1. 建立不少于 200 份的冻结测试集，覆盖采购、销售、服务、劳动、软件开发五类合同，每类不少于 30 份；PDF 与 DOCX 均不少于 40%，扫描件不少于 20%；
2. 由两名业务人员独立标注，争议字段由第三人裁定；测试集在赛前冻结，不参与提示词、规则或模型调试；
3. 标量字段以“合同数 × 应评字段数”为分母，标准化后完全匹配计为正确；预期空值只有在系统同样输出为空时计为正确，不得通过大量空字段抬高分数；
4. 多值字段按规范化后的值集合计算微平均精确率、召回率和 F1；甲乙方、金额、期限、付款节点另行统计召回率；
5. 总体关键要素得分采用各字段得分的宏平均，不由高频字段加权；通过标准为总体得分不低于 90%、核心字段召回率不低于 95%、任一核心字段得分不低于 85%；
6. 输出总体、各字段、各合同类型、原生文档/扫描件分组结果、95% 置信区间和主要错误案例。

### 12.4 风险识别评测

建立不少于 100 份合同、300 个已标注风险点的冻结风险集，其中高风险不少于 80 个，覆盖正常、缺失、矛盾、违法、权责失衡和财务异常。风险识别通过标准为高风险召回率不低于 90%、整体 F1 不低于 85%、伪造法规引用为 0、可验证依据率不低于 98%。

修改建议从风险集中分层抽取不少于 100 条，由两名法务/财务专家按“法律或财务正确性、完整性、可执行性、是否编造事实”四维独立评分，争议由第三人裁定。五分制平均分不低于 4.0、达到 4 分及以上的建议比例不低于 85%，不得出现可能导致合同无效、重大损失或违法的严重建议。任何模型升级均需通过相同回归评测。

### 12.5 批量处理验收

批量测试使用 FR-03 冻结的 50 份有效合同与 2 份异常文件，记录总页数、文件格式、扫描比例、总完成时长、成功率、失败隔离、重试结果和资源峰值。通过标准为 30 分钟内完成、有效文件成功率不低于 98%、异常文件均被正确隔离、刷新后进度可恢复，并且不存在整批中断或重复合同记录。

### 12.6 关键埋点

记录上传开始/完成、解析成功/失败、审查开始/完成、风险查看、复核状态变更、建议复制/应用、整改创建/关闭、报表筛选、导出开始/完成和知识库变更。埋点不得携带合同正文和敏感字段值。

## 16. 总体验收与发布门槛

1. P1 功能全部通过正常、空状态、错误状态和权限测试；

5. 法务与财务 Agent 的独立输出和合并结果可追踪，跨域冲突具有明确裁决人和升级路径；

8. 合同原文、模型调用、导出和权限变更均有安全控制与审计记录；
9. 不存在阻断主流程的 P1 缺陷，P2 缺陷有明确规避方式；
