# 契鉴三项创新点定稿

本稿定位为应用与工程机制创新，不宣称算法首创。表述以当前代码机制为依据，效果判断以独立评测为依据。

## 一、法财职责分离与受控交叉复核

**PPT标题：法财分工审查，分歧留给人工裁决。**

契鉴将法务条款审查与财务交易核对分为独立职责，首审阶段相互不可见，随后通过受控结构化事实交接开展交叉复核，保留专业分歧并提交人工处理。

答辩说明：法务侧关注权利义务、违约、争议与知识产权；财务侧关注金额、付款、发票与结算。Agent指职责角色，可以共用同一个底层模型。重点是两类职责独立检查、受控交接、分歧可见。

实现证据：backend/app/services/audit/agent_profiles.py、collaboration.py、auditor.py、secondary_review.py。

边界：当前独立首审为顺序执行；交叉复核和发布受预算、证据状态及配置约束。本次实验只比较独立首审分工，不能证明完整交叉复核的收益。完成盲评前不写“双Agent优于单Agent”或“准确率提升”。

## 二、原文、依据与决策关联的风险证据链

**PPT标题：风险关联原文，依据与处理状态可查。**

契鉴把风险候选与合同原文位置、检索依据标识及决策记录关联，对无法定位、依据未核验或存在冲突的结果保留明确状态，支持人工逐项核验。

答辩说明：评委看到的不只是“有风险”，还应能看到对应哪段原文、用了什么依据、依据处于什么核验状态，以及为什么转人工。

实现证据：backend/app/services/audit/auditor.py、claims.py、evidence_validation.py、decision.py、evidence_state.py。

边界：关联和定位可提高核验便利性，不保证法规适用正确；RAG命中不等于法律正确。默认manual_only模式不能称为自动完成法律语义验证。

## 三、分级人工介入与整改交付留痕

**PPT标题：从风险发现到人工处置、整改和报告交付。**

契鉴将风险分级连接到授权人员的确认、修改或忽略意见，结合整改跟踪和报告导出保留处理记录，使审查结果能够进入后续业务工作。

答辩说明：系统给出风险候选，授权人员作出业务决定。人工动作包含身份、时间和理由，整改与报告延续同一份审查记录。

实现证据：backend/app/api/v1/endpoints/risks.py、rectifications.py、backend/app/services/report/exporter.py、operations.py及风险授权检查。

边界：功能和记录链路不等于真实企业效率改善已测得；本次实验不测终审法律有效性、生产任务可靠性或整改完成率。

## 30秒统一口径

契鉴面向企业合同审查中标准不统一、专业意见分散、后续处理难追踪的问题，构建法财分工审查、风险证据关联和分级人工处置三项机制。系统协助发现和定位风险，并把依据、专业分歧和处理记录留给授权人员核验，最终连接到整改与报告交付。

## 结果出来后才可补充的句式

“在20份合成合同、同一模型、3次重复的内部实验中，双Agent相对通用两轮对照的〔指标〕为〔数值〕，实际Token为〔数值〕。结果仅反映本样本范围。”

如果只优于单轮、不优于通用两轮，应说“额外审查调用可能改善覆盖，尚未证明专业分工具有独立优势”。如果差异不明确，保留职责分工与审计机制的特色，删除效果优越性主张。

2026-10-31补充：用户授权的AI法务/财务角色模拟标注与裁决用于内部排查。它与被测系统共用同一模型，不能充当独立专家金标，也不能用其覆盖率替换上文的人工效果指标。三项创新的机制表述继续有效，性能优势须另有独立证据。

本轮AI参考覆盖观察：S1为227/372（61.0%），S2为243/372（65.3%），D2为221/372（59.4%）。372是124项AI参考在3次重复下的实例总数，不是372份合同。D2相对S2的财务覆盖略高、法务覆盖较低，整体未出现覆盖优势。因此本次不采用“单Agent对照已证明双Agent更准确”的表述，也不从本结果推出真实法律效果优劣。
