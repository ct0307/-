# 单 Agent 与法财双 Agent 小规模对照协议 v1

## 实验问题与边界

判断专业分工是否改善风险发现，而非为双 Agent 预设胜利。比较独立首审的专业分工，不测完整产品的RAG、交叉复核、确定性规则或UI；均不引入检索依据，不测法规正确率。完整产品验收另行进行。

## 样本冻结

从用户提供的原始文件读取文本，不从生成器重建正文。保留原文件散列和抽取、清理后散列；DOCX接受插入并排除删除和批注，PDF不启用OCR。移除合成标签、案例编号、文本状态、PDF页眉页脚；仅删除明确泄露答案的评价句，保留其前面的交易责任安排。清理记录保存在本地输出中。

6份buyer_standard作为开发集；20份测试覆盖supplier_standard、business_draft、legal_redline、model_contract、online_terms、framework_order、master_supplement。测试中含15份原构造actionable及5份negotiated；构造分层不是风险真值，negotiated不代表无风险。缺少经人工确认的无风险对照，保留为限制，不臆造金标。同源模板偏差仍存在，禁止外推真实企业总体。

## 三组与预算

- S1：通用Agent一次，覆盖法务+财务全部清单，每次最大输出3200 tokens。
- S2：同样的通用Agent两次独立审查，取并集；每次最大输出1600 tokens。
- D2：法务、财务各一次独立审查，取并集；每次最大输出1600 tokens。

使用同一模型及服务端配置、同一完整文本和提示词公共部分，temperature=0.2，重复3次；按固定种子打乱全部实验单元顺序。S2和D2的调用数、输入文本次数及输出上限一致，实际Token仍可能不同。S1与D2只做实际资源对比，不称严格等算力。单元内部顺序调用，单元之间最多3并发以缩短总运行时间；延迟是共享负载下的耗时，不是产品并行性能指标。总计20×3×(1+2+2)=300次请求。无自动重试，每次失败、截断、部分成功均计入记录，禁止当成功。

法务/财务职责直接复用项目agent_profiles；通用组获得两者完整清单。三组共用风险输出字段，不能因通用组缺少任务信息而人为削弱基线。双组不传递首审结论，不自动合并相反观点；保留来源。相同维度、原文与问题说明完全一致时去重，语义近重复由盲评去重，不当作额外命中。

## 标注与评分

模型输入不包含标签、候选问题或构造风险等级。抽取后的候选审阅位置只是工作底稿，不能作金标准。法务及财务人员先独立审阅全部测试文本，列出风险类型、严重性、原文引用与判定理由；分歧由第三人裁决，冻结标签后进行正式实验。模型输出打乱为匿名A/B/C，映射另存；复核人员不得查看映射。

每条输出与冻结标签按问题实质和原文位置人工匹配，一条真值最多匹配一次。未匹配输出逐条裁决为误报、新发现真风险或重复；新发现真风险须更新统一标签并重评所有组，不能只为某组增补。原文存在只是引用有效，不证明风险成立。无标注不输出Precision/Recall/F1。

按重复轮次和合同汇总TP/FP/FN、分法务/财务召回、精确率、F1、有效原文引用比例、请求成功与截断比例、Token和耗时。失败合同保留在总样本中，质量指标同时报告成功子集及全样本结果。无预测时Precision为未定义，无正例时Recall为未定义。小样本仅描述趋势；3次重复不是60份独立合同。若估计区间，以合同为单位配对重采样，同一合同3次绑定，不把重复当独立样本。

## 结果口径

无授权模型：模型实验未执行。无人工冻结标签：法律效果未测量。Mock测试只能证明工具行为，不能填充实验结果。若D2仅优于S1而未优于S2，只能说明额外调用可能带来收益；不宣称已验证专业分工优势。存在权衡时同时报告成本、误报和召回，不挑选有利指标。

## 运行中观察到的服务偏差

部分响应的completion_tokens超过请求max_tokens，例如请求1600而服务返回2371且finish_reason=stop。客户端确实发送了max_tokens；尚未核实服务端执行和计数口径，不能据此断定是模型正文Token还是包含其他开销。逐组记录此偏差，不中途更换参数。本轮只满足相同调用次数与相同请求预算参数，不能宣传严格等实际算力。
