# 证据驱动审查 V0-V4 消融协议

## 目的

在同一批脱敏合同、同一金标准、同一模型和同一知识库快照下，隔离提示词、规则、精排和支持关系校验的增量贡献。比较器要求五个版本完整存在，并校验 `frozen_context` 与 `gold_sha256` 一致。

## 版本定义

| 版本 | 唯一新增范围 |
|---|---|
| V0 | 当前基线 |
| V1 | Claim 契约、Prompt Registry、法务/财务独立首审 |
| V2 | 版本化确定性规则与规则执行轨迹 |
| V3 | RAG 查询计划、适用性判断与可降级精排 |
| V4 | Support V3 五层证据校验与统一决策门禁 |

除表中范围外，模型版本、温度、知识库、数据集、环境和输出预算必须固定。每个运行记录 `prompt_version`、`rule_version`、`reranker_version`、`support_validator_version`，作为可审计的组件变量。

## 数据与标注

开发、验证、盲测按合同级拆分，禁止同一合同跨集合。金标准由两名具备法务/财务经验的标注者独立完成，分歧提交第三人仲裁；保存标签版本、标注规则和哈希，不在评测产物中保存合同正文。

## 指标

至少报告风险 Precision/Recall/F1、高风险召回、Unsupported Claim Rate、错误自动接受率、人工复核率、Unique Contribution Rate、Claim Correction Rate、冲突率、P50/P95 延迟、Token 和成功率。缺少真实证据的指标输出 `null`，报告文案显示“未测量”，不得填零或写成达标。

## 供应链与外发边界

精排模型下载前记录来源、许可证、版本、文件哈希和缓存目录，并取得合同数据是否离开本机的授权。未获授权时保持精排禁用或使用可复现的假模型。真实专家金标、PostgreSQL、GPU/OpenClaw 和能耗数据未执行时，交付材料标记“代码就绪待实测”。

## 失败规则

缺失 V0-V4、冻结上下文不一致、金标准哈希不一致、指标为 NaN/无穷或输入包含合同原文时，评测退出并返回失败，不生成可误读的比较结论。
