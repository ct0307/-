# 决赛演示问题处理方案与实施计划

**目标：** 修复彩排发现的局部断点，以可复验的真实流程支撑决赛演示。

**方案：** 沿用Vue、Element Plus、FastAPI、现有数据库和权限。相较于大范围重构或仅绕开问题演示，选择补齐已有入口、状态和验证，控制回归范围。用户已授权制定方案并落地实现。

## 1. 合同日期确认

- 修改 contracts 接口、contract schema、审查页面和接口封装；补充前后端行为测试。
- 显式确认有效日期，保存确认者与时间并记录审计。自动提取的值不能自动视为确认。
- 未解析、无权限、正在审查的请求不得写入；改变日期后已有依据/结果不得继续冒充当前有效结论。
- 日期、解析、风险复核和终审通过合同条件写入保护并发；重审仅清理当前任务待复核结果，保留历史风险与条款锚点。
- 报告仅采用当前合同代次；日期变化尚未重审时明确待重审，历史整改继续保留。旧台账的空列表仍按原约定导出全部授权合同。
- 验收：确认后法规适用时点可读取；刷新仍有确认记录；错误日期及无权限被拒绝；保持人工依据核验边界。

## 2. 整改材料解析

- 修改 RectifyView.vue、必要的原文查看组件与 rectification-closure.spec.ts。
- 上传成功后调用现有parse接口，解析成功再提示可读；失败保留已上传材料，明确提示并允许重试。
- 历史未解析材料在原文入口可重新解析。解析不会触发audit模型接口。
- 验收：责任人上传，独立复核人可查看正文；解析错误时不能宣称成功，不需重复上传。

## 3. 终审与前置条件

- 修改 CollaborationView.vue、api/workflow.ts、后端workflow状态计算和相关测试。
- 使用组件表单代替window.prompt，收集终审意见、必要质量说明及逐项冲突裁决；去空格校验，失败保留输入，成功才关闭。
- 后端查询与发布复用同一缺整改任务判断；查询返回缺项风险，前端列清单并引导补齐；发布仍保留服务端校验与版本校验。
- 验收：空输入不发请求；错误明确且可重试；缺任务不能发布；满足条件后成功，刷新仍为已发布。

## 4. 知识条目纠错

- 定位旧种子来源，修正违约金规则与定金20%条款引用。
- 对已有数据库提供窄范围、可预览、幂等的修复入口；只匹配已确认错误，不覆盖其他人工编辑，不提升审批或证据信任。
- 验收：现有精确匹配错误已修订，重复执行不造成额外更改；原上传TXT不在仓库，后续导入应采用受控纠错资源中的修订文本，不声称可自动纠正任意新上传内容。

## 5. 演示节奏与细节

- 复核弹窗改中文确认/取消。
- 编写现场手册：会前启动真实任务、现场展示可恢复进度与证据、等待过长时切换明确标识的已完成样例/录屏，演示人工复核边界。
- 不以单样本猜测性能参数或降低模型核验质量。

## 验证顺序

先写关键行为回归并运行确认失败，再实现最小修改，运行对应测试；随后执行项目完整质量门禁。浏览器使用隔离库复验正常、空、错误、窄屏与刷新恢复，保留截图及接口证据。通过独立复核后汇总已验证与未覆盖内容。

不安装依赖、不改CI/CD、不部署、不写密钥或真实合同原件。变更保留在本地修复分支，不自动提交或发布。
