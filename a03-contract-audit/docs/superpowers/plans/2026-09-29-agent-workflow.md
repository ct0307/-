# Agent 审查工作流实施计划

用户已批准上一轮架构建议，由主代理顺序实施，不使用子代理。复用当前分支和用户已有修改，不提交、不部署、不安装依赖。

目标：将规则交叉告警接入有界定向复查，保留多 Agent 观点并归并主风险，以代次绑定的人工终审形成业务发布状态。

技术：现有 FastAPI、SQLAlchemy、Vue、pytest、Playwright。机器审查状态与人工终审状态分离。

- [x] 新增 workflow.py，测试跨 Agent 精确同问题归并、定向复查的角色/引用约束、预算与失败降级；只保守归并同类别同原文，保留所有观点。
- [x] 新增运行预算与版本指纹；接入 auditor、窗口检查点和 runner。模型、提示词、正文、规则变更使检查点失效；复查最多一轮且不能提升证据可信度。
- [x] 新增 AuditWorkflow 表和迁移、GET/POST 终审接口；测试授权、过期代次、并发版本、缺失意见、未复核风险、未裁决冲突、解析质量确认和成功发布。
- [x] 协同页接入工作流状态，展示主风险及复查，并提交终审意见；恢复/证据/窄屏回归通过。
- [x] 真实语义模型继续保持离线/人工门禁，未把未评测模型接入生产自动采信。
- [x] 专项测试、类型与构建、浏览器回归；更新改进台账及验收边界。

验收重点：重新审查或人工意见改变后旧终审失效；人工终审不得清除机器/OCR标记；没有可信依据不能因多个 Agent 同意而自动成为 supported；失败复查保留人工待办。
