# 合同上传与解析可靠性修复设计

## 背景

三份文本型 PDF 经单合同上传入口逐次拖拽后，出现两类问题：部分文件已上传但解析失败，界面只显示通用错误；后续成功文件覆盖此前文件的页面展示。数据库确认文件未丢失，失败集中在 PDF 文本兼容字符、日志编码和单会话状态模型。

## 目标

- 包含 Unicode CJK 部首兼容字符的文本型 PDF 可以稳定解析。
- 日志输出失败不能中断合同解析。
- 前端明确区分上传失败、上传成功但解析失败、解析成功。
- 解析期间不允许再次发起单文件上传。
- 页面保留当前审查合同，同时展示本次上传记录并允许切换已解析合同。
- 合同原件、数据库和运行日志不进入版本控制。

## 非目标

- 不合并单合同与批量合同的后端接口。
- 不删除现有重复上传记录。
- 不改变合同审查、批次审查或历史记录的数据模型。
- 不对所有输入文本无条件执行可能改变法律符号的全量规范化。

## 方案

### PDF 解析

`pdfplumber` 提取后检查 U+2E80 至 U+2FDF 范围内的 CJK 部首和康熙部首字符，不把 U+2FF0 至 U+2FFF 的表意文字描述字符一概判为乱码。仅当兼容部首达到 3 个或占非空字符 1% 以上时，才认为字体映射不可靠并生成 PyMuPDF 候选。

只有当 PyMuPDF 候选页数完整、非空文本长度不少于原候选的 70%、兼容部首更少且 CJK 可读字符比例不下降时才替换原候选。候选不达标时保留原文本，并仅对 U+2E80 至 U+2FDF 范围内的单个字符执行 NFKC 映射；现有空页 OCR 流程保持不变。解析结果必须保留页级文本完整性，不能因回退静默丢页。

### 日志防护

后端日志初始化时将标准输出配置为 UTF-8；无法配置时使用 `backslashreplace` 安全替换。业务代码不得因控制台编码能力不足而失败。解析日志只记录命中的字段名、字段数量、文本长度和布尔信号，不记录甲乙方、金额、地址等字段值，也不记录合同全文。

### 前端状态

单合同上传拆分为两个明确阶段：上传、解析。选择文件后立即创建记录，状态按 `uploading -> upload_failed` 或 `uploading -> parsing -> parse_failed / parsed` 转换。解析成功后才设为当前合同；解析失败则保留合同 ID、安全错误码和中文说明，不显示绿色成功状态，并允许用户调用现有 `POST /contracts/{id}/parse` 手动重新解析，不能通过重新上传实现重试。

`audit-session` 增加仅存在于当前登录会话内的上传记录列表，不写入新的后端表。列表只记录本地记录 ID、文件名、合同 ID、状态、安全错误码和中文说明，不保存合同正文或结构化要素。重置当前工作台、退出登录或身份切换时清空列表；普通路由切换不清空，浏览器刷新后允许列表消失，历史记录仍以数据库为准。

用户可切换已解析合同作为当前审查对象。切换时先原子清空上一合同的要素、风险、交叉验证、OCR 状态、审查进度和合同类型，再按合同 ID 重新调用解析接口取得要素并设为当前合同；只有全部成功才提交新状态，失败时保持原当前合同不变。上传或解析进行中禁用单文件上传入口，避免并发覆盖。

### 错误展示

解析端点将可预期错误映射为稳定错误码和经过脱敏的中文说明，例如 `PDF_TEXT_ENCODING_ERROR`、`PDF_TEXT_EMPTY`、`OCR_UNAVAILABLE` 和 `PARSE_INTERNAL_ERROR`；不得把文件路径、堆栈或第三方异常原文返回前端。现有成功响应保持兼容，错误响应使用统一 `{ code, detail }` 结构。

前端优先显示统一 API 客户端提供的安全中文 `error.message`，并保留 `error.code` 用于状态记录。通用兜底文案仅用于没有可用错误信息的情况。错误记录在上传区持续可见，不能只依赖短暂 toast。

## 测试

- 后端：兼容部首阈值、PyMuPDF 优质/劣质候选、局部 NFKC、CP936 不可编码字符日志、脱敏错误契约、普通 PDF 和 OCR 路径不回归。
- 前端 store：五态转换、上传失败、解析失败、手动重试、解析成功、禁止并发、合同切换成功与回滚、注销清理。
- 前端页面：持续错误说明、多记录同时显示、当前合同切换、空记录状态、忙碌状态禁用，以及 390x844 和 1440x900 响应式显示。
- 集成验收：三份真实 PDF 只在本地执行，不复制进仓库；确认两份原失败合同可解析，三份同时出现在本次记录中，控制台无错误或警告。
- 完成门禁：运行相关后端测试、前端测试、`vue-tsc --noEmit`、Vite 生产构建和 `scripts/quality_gate.ps1`。

## 风险控制

- 前端上传记录不存储合同正文或结构化要素，只保存最小状态元数据。
- 不自动重试已失败上传，避免产生更多重复合同。
- 保持现有 API 契约兼容，降低其他页面回归风险。
