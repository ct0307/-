# 契鉴多主题切换设计规格

## 目标

在不修改后端、接口、权限和业务流程的前提下，为契鉴增加可持久化的外观模式切换。默认保留具有法律文书辨识度的卷宗主题，同时提供企业明亮、深灰审阅和跟随系统模式。

## 外观模式

| 存储值 | 显示名称 | 行为 |
|---|---|---|
| `dossier` | 卷宗主题 | 默认模式，使用原有米白纸张、黄铜和印章红视觉 |
| `light` | 企业明亮 | 使用当前冷灰页面底和白色工作面 |
| `dark` | 深灰审阅 | 使用深灰工作底和低眩光审阅面 |
| `system` | 跟随系统 | 根据 `prefers-color-scheme` 映射为企业明亮或深灰审阅 |

`system` 是自动选择模式，不是第四套配色。操作系统主题发生变化时，页面应立即更新，不需要刷新。

## 默认与持久化

- 首次访问或本地存储不存在时使用 `dossier`。
- 用户选择写入浏览器 `localStorage`，存储键为 `qijian-theme-mode`。
- 读取到未知值、空值或异常时回退为 `dossier`。
- 在 Vue 应用挂载前设置根元素主题属性，避免刷新时出现错误主题闪烁。
- 当前版本不增加账号级同步，但主题模块应保持独立，便于未来接入用户偏好接口。

## 视觉规则

- 所有页面和组件通过语义化 CSS 变量取色，不在业务组件中分散维护主题颜色。
- 三套视觉主题共用布局、间距、圆角、字体层级和交互结构。
- 黄铜用于品牌、主操作和选中状态，不作为普通装饰色滥用。
- 高风险红、预警琥珀、合规绿在所有主题中保持相同业务含义。
- 文本、边框、表格、弹窗、抽屉、图表和焦点状态必须分别校验可读性，禁止通过简单颜色反转生成深色主题。
- 尊重现有 `prefers-reduced-motion` 行为，不增加无业务意义的主题切换动画。

## 交互设计

- 在应用顶栏通知按钮附近增加主题图标按钮。
- 点击后打开单选菜单，依次显示：卷宗主题、企业明亮、深灰审阅、跟随系统。
- 当前模式显示选中标记，按钮悬停提示为“切换外观”。
- 选择后立即生效并关闭菜单，不增加确认按钮。
- 移动端使用相同入口，按钮保持固定尺寸，菜单不得超出视口。
- 登录页与主应用共享同一主题选择结果；登录页不额外显示主题入口。

## 模块边界

### 主题状态模块

负责模式类型、默认值、持久化、根元素属性和系统主题监听。对组件暴露当前模式、实际生效主题和切换方法。

### 主题选择组件

只负责展示菜单与调用主题状态模块，不直接操作 DOM 或 `localStorage`。

### 设计令牌

在全局样式中分别定义 `dossier`、`light`、`dark` 的语义变量。业务页面继续使用现有变量名，避免主题功能侵入业务组件。

## 数据流

1. 应用启动时读取 `qijian-theme-mode`。
2. 校验模式值，非法值回退为 `dossier`。
3. 若为 `system`，读取系统明暗偏好并订阅变化。
4. 在根元素写入实际主题，例如 `data-theme="dossier"`。
5. 用户通过顶栏选择模式后更新状态、持久化并重新应用主题。

## 异常处理

- `localStorage` 不可用时仍允许当前会话切换，刷新后回到卷宗主题。
- 系统主题 API 不可用时，`system` 回退到企业明亮。
- 主题值解析失败时不得阻断应用启动。
- 切换主题不得重置路由、表单、审查结果或抽屉状态。

## 验收标准

- 未保存偏好时默认显示卷宗主题。
- 四个菜单选项均可选择，当前项标记正确。
- 手动选择卷宗、企业明亮或深灰审阅后立即生效，刷新后保持。
- 跟随系统模式能响应明暗变化，切换到手动模式后停止跟随。
- 登录页和主应用使用一致的生效主题。
- 1440x900、1920x1080、390x844 下入口与菜单无溢出、遮挡和布局跳动。
- 合同审查、风险抽屉、知识库、报表、历史记录的正常、空、错误状态在三套主题下可读。
- Console 无相关 warning/error，类型检查、生产构建和完整 Playwright 测试通过。

## 范围外

- 账号级跨设备同步。
- 用户自定义任意颜色。
- 后端数据库或接口改造。
- 新增第三方主题依赖。
- 改变风险等级、审查算法或业务状态机。
