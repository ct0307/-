# 契鉴比赛交付收口设计

## 目标

以比赛提交和答辩得分最大化为第一优先，在不继续扩展非评分必需功能的前提下，将现有系统、验证证据和参赛材料整理为一致、可复核、可演示的正式交付包。

## 当前基线

- 核心业务闭环已经贯通：合同接入、解析、双 Agent 审查、逐风险 RAG 证据、人工复核、整改和报表。
- 后端当前全量测试为 142 passed、1 skipped；前端当前常规测试为 13 passed、6 skipped；TypeScript 检查和生产构建通过。
- 项目详细方案 Word/PDF 已完成；项目概要 Word/PDF 已生成并通过结构校验。
- 企业法务工作台和多主题切换仍位于未提交工作区，尚未完成本轮浏览器验收和正式进度归档。
- OCR 冻结样本准确率、52 份批量吞吐、目标 Compose 环境和硬件对照仍缺正式实测证据。

## 交付策略

采用“评分证据驱动收口”，按依赖关系依次完成五个阶段。前一阶段形成稳定证据后再进入下一阶段，避免文档、PPT 和视频引用尚未确认的数据。

### 阶段一：稳定代码基线

1. 审查未提交前端改动与新增主题模块，确认没有混入无关功能。
2. 验证桌面端与移动端的页面身份、正常状态、空状态、错误状态、主题切换、关键交互、控制台和横向溢出。
3. 运行前后端测试、类型检查、生产构建和差异检查。
4. 更新 README 与 PROGRESS，使项目概要、前端升级和最新测试数量与实际状态一致。

退出条件：代码验证零失败；已知跳过项有明确原因；进度文档不再使用过期口径；未验证内容不得标为完成。

### 阶段二：补齐硬指标证据

1. 使用授权、脱敏、冻结的数据集测量 OCR 字符准确率和合同要素准确率。
2. 使用固定的 50 份有效文件和 2 份异常文件验证批量吞吐、失败隔离和复核边界。
3. 在目标 Docker Compose 环境验证迁移、健康检查、服务依赖和基础业务链路。
4. 条件具备时完成 OpenClaw 或目标算力环境的延迟、吞吐、成功率和成本对照；条件不具备则明确写为未测。

退出条件：每项结论均能追溯到数据集哈希、环境说明、命令、原始结果和汇总结论；不得用单样本结果替代总体准确率。

### 阶段三：制作参赛材料

1. 测试报告：汇总功能、接口、异常、性能、准确率、安全和兼容性证据。
2. 测试用例：覆盖前置条件、步骤、预期结果、实际结果、证据位置和结论。
3. 项目简介 PPT：围绕赛题问题、创新方案、核心闭环、技术可信度、验证结果、应用价值和团队执行展开。
4. 团队过程材料：按角色、里程碑、决策、问题和产出记录真实协作过程。
5. 演示脚本与视频：在 3 至 5 分钟内展示上传、解析、双 Agent 审查、证据溯源、人工复核、整改和报表闭环。

退出条件：材料引用的所有数字均来自稳定基线或正式实测；每项评分主张至少有一份可检查证据。

### 阶段四：一致性审查

建立统一事实表，逐项核对系统界面、README、PROGRESS、详细方案、项目概要、测试报告、PPT 和视频口播中的功能名称、测试数量、知识库口径、准确率、部署状态和责任边界。

退出条件：不存在同一指标多种数值，不把历史本机结果写成新环境默认能力，不把 AI 辅助意见描述为法律裁决。

### 阶段五：交付封版

1. 按源码、部署、文档、测试证据、演示材料和第三方声明整理目录。
2. 验证文档可打开、链接有效、编码正常，源码可按说明构建。
3. 生成最终文件清单和 SHA-256 校验值。
4. 保留一份只读封版副本，后续修改通过新版本进行。

退出条件：交付目录可以由未参与开发的评审人员独立理解、启动和核验。

## 优先级

| 优先级 | 内容 | 原因 |
|---|---|---|
| P1 | 代码基线、浏览器验收、进度口径、测试报告、PPT、演示脚本 | 直接影响项目可用性、可信度和主要评分项 |
| P1 | OCR、批量吞吐、Compose 等硬指标证据 | 当前最明显的可验证性缺口 |
| P2 | 团队过程材料、协作验收包、演示视频成片 | 完成交付完整性并增强答辩说服力 |
| P3 | 第三方弃用警告、前端包体优化、开发环境可移植性 | 不阻塞当前比赛交付，可在封版前择机处理 |

## 质量与风险控制

- 不删除、重置、强推、安装或降级依赖、修改 CI/CD、部署、合并、提交业务改动或推送远端，除非已获得对应授权。
- 现有未提交内容视为用户资产；按主题识别边界，不覆盖来源不明的改动。
- 测试通过不能替代浏览器验收，浏览器演示不能替代准确率与吞吐实测。
- 无法验证的能力统一标记为“待实测”或“未验证”，并说明所缺环境、数据或权限。
- 每个阶段结束时更新项目进度记录，保留验证命令、结果和证据位置。

## 完成定义

项目只有同时满足以下条件才可标记为比赛交付完成：

1. 核心代码基线可构建、自动化测试零失败、主要页面浏览器验收通过。
2. 所有强指标有可复核证据，或明确、诚实地标记外部验收边界。
3. 详细方案、概要、测试报告、测试用例、PPT、团队材料和演示视频齐备。
4. 系统与全部材料使用同一事实口径和责任边界。
5. 最终交付包有目录、启动说明、版本标识和校验值。
