# 审查失败可见性与安全提速设计

## 已确认范围

用户批准按诊断推荐顺序改进：先修复失败原因展示，再验证批量模型调用，最后核对异步批次吞吐。此次不安装依赖、不修改 CI/CD、不部署、不写入真实业务数据库。

## 方案取舍

| 方案 | 优点 | 局限 |
|---|---|---|
| 仅前端显示 review_reason | 修改小 | 后端错误码、可重试性仍不一致 |
| 统一失败契约（采用） | 原因、动作、历史兼容可端到端验证 | 需同步修改接口与前端 |
| 失败详情抽屉与时间线 | 信息全面 | 超出本次必要范围 |

## 失败契约

- 复用现有 `error` 和 `error_code`，增加 `retryable`、`error_action`；不新增数据库表或迁移。
- 质量门返回 `audit_failed` 时，执行器保存安全错误码与摘要，而不是清空错误字段。
- 历史失败记录缺少错误字段时，批次 Schema 从该任务自己的 `result_json` 读取 `issues/quality_reasons/review_reason`，不使用合同最新审查原因冒充旧任务原因。
- 文案仅由已知错误码映射生成；不向用户暴露模型原始 detail、异常堆栈、合同正文、密钥或绝对路径。未知错误使用通用安全文案。
- 多原因按结构化错误码去重；重审不重复追加旧质量原因，既有要素人工复核要求仍保留。
- 同时有多个原因时，临时模型错误优先解释此次未完成原因；缺失覆盖率不是可以自动采信部分结果的理由。

| 类型 | 示例 | 处理方式 |
|---|---|---|
| 临时服务异常 | 超时、服务不可用、存储暂不可用 | 可重试，提示检查服务状态 |
| 模型输出失败 | 截断、格式无效、分页未完成 | 可重试，反复失败联系管理员 |
| 供应商拒绝 | MODEL_REJECTED | 不盲目重试，检查凭据、额度或服务策略 |
| 输入质量不足 | 缺页、文本不完整、OCR 低质量 | 重新解析或人工核对 |
| 证据/事实问题 | 未核验、冲突、事实校验失败 | 人工复核，不放宽质量门 |
| 内部异常/未知原因 | AUDIT_INTERNAL_ERROR | 联系管理员并提供批次号 |

## 前端与重试

- 每个失败项始终展示安全原因、错误码和处理建议；兼容旧响应的 `error/review_reason`。
- 批次重试只重新派发可重试项，前后端同时执行筛选，不能仅隐藏按钮。
- 批次全部为不可重试失败时隐藏批次重试按钮。
- `review_required` 继续展示原因与部分结果，不归入失败，不提供无意义重试。
- 保持现有页面布局，桌面与 390px 移动端长文案换行，无横向溢出。

## 安全提速

- 保留现有解析缓存、RAG 快照、窗口并发与主线程顺序持久化。
- 不并行法务与财务 Agent，不扩大 8000 字窗口，不跳过事实、原文、证据或二次复核校验。
- 比较基线（两批量开关关闭）与候选（两批量开关开启），同合同集、模型、提示词、知识修订、维度、并发和时限必须一致。
- 优先复用现有 `evaluation/audit_performance.py` 与 CLI；先检查是否已覆盖所需门禁，只补缺口，不重复造工具。
- 质量门要求高风险召回、F1、证据支持、完整覆盖不下降；跨 claim 证据引用及未核验自动发布均为零；观察人工复核比例是否异常上升。
- 质量指标或身份元数据缺失时报告 blocked，不能把合成 fixture 等价测试当成真实模型质量成绩。
- 质量通过后评估调用数、P50/P95 和失败率，再批准启用批量开关。条件不足时保持代码、示例配置和本机配置关闭。
- PostgreSQL/Redis/Celery 已有生产并发 2 配置，本次核对和提供验收入口，不未经确认部署或迁移业务库。
- 真实公网模型 A/B 需要明确授权费用和数据外发；本次先完成本地回归与门禁准备，未授权不调用公网模型。

## 验证与交付

1. 后端先写失败快照、脱敏、重试筛选与历史兼容测试，确认红灯后实现。
2. 前端先写可重试/不可重试/历史原因用例，确认红灯后实现。
3. 运行批量、缓存、并发与质量门回归；补齐必要的评测输入一致性测试。
4. 浏览器覆盖正常、空、可重试失败、不可重试失败和移动端状态。
5. 运行完整质量门禁，报告实际通过数、跳过项和外部实测限制。

验收：用户不再只看到失败与重试；旧失败记录无需覆盖即可展示；重试服务端正确筛选；原有风险质量边界不变；无真实 A/B 证据时不宣称提速达标。
