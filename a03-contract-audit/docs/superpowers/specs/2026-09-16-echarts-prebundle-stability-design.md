# ECharts 预构建稳定性设计

## 问题

多维报表的数据请求已经成功，但 Vite 开发服务器为 `echarts/core`、`echarts/charts`、`echarts/components` 和 `echarts/renderers` 生成了不一致的依赖实例。组件注册发生在一个实例中，图表渲染使用另一个实例，最终触发 `xAxis \"0\" not found`，并让加载遮罩残留。

## 方案

在 Vite 的 `optimizeDeps.include` 中显式列出四个现有 ECharts 子路径，让启动阶段一次性发现并预构建完整依赖图。保留现有按需引入和生产分包，不修改图表组件、接口或业务数据。

## 验证

1. 配置契约测试断言四个子路径全部存在。
2. 页面冒烟测试使用固定报表数据，断言加载遮罩消失并渲染四个 canvas。
3. 冒烟测试收集控制台和页面异常，拒绝 ECharts 组件缺失、坐标轴缺失与 mounted hook 错误。
4. 运行类型检查、生产构建和真实浏览器验证。

## 边界

- 不升级或安装依赖。
- 不改变后端、接口协议和图表视觉设计。
- 不通过整包引入 ECharts 掩盖预构建问题。
