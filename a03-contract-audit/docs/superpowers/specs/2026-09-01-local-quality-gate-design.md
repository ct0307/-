# 本地一键质量门禁设计

## 1. 背景与目标

项目已经分别具备后端 pytest、前端 Playwright、TypeScript 类型检查、Vite 生产构建和评测流水线专项测试，但缺少统一、可重复的本地验收入口。比赛前继续修改代码时，人工逐条执行命令容易漏项，也无法形成统一的机器可读结果。

本功能提供一个面向 Windows 开发环境的一键质量门禁。默认模式只运行当前电脑可以稳定完成的开发与自动化测试；可选 E2E 模式负责启动本地前后端、等待服务就绪、执行浏览器测试并回收自身创建的进程。

本功能不证明真实 52 份合同、PostgreSQL 16、Docker Compose、OpenClaw、GPU 或功率数据已经完成实机验收，也不得把自动化测试结果写成赛题硬指标达标。

## 2. 范围

### 2.1 包含

- Windows PowerShell 一键入口。
- Python 核心执行器，不新增第三方依赖。
- 评测流水线专项测试。
- 后端全量测试。
- 前端 Playwright 测试。
- TypeScript 类型检查。
- Vite 生产构建。
- 可选的本地服务型 E2E。
- 失败即停止、明确退出码、阶段耗时和 JSON 汇总。
- 执行器自身的 pytest 自动化测试。

### 2.2 不包含

- GitHub Actions 或其他 CI/CD 修改。
- 依赖安装、升级或降级。
- Docker、PostgreSQL、OpenClaw、GPU 或真实数据验收。
- 自动提交、推送、部署或修改 Git 分支。
- 保存测试进程的完整环境变量、密钥或业务数据。

## 3. 方案选择

采用“Python 核心执行器 + PowerShell 薄入口”。

- Python 负责步骤编排、命令执行、失败处理、耗时统计、JSON 报告、健康检查和子进程生命周期。
- PowerShell 只负责定位仓库、选择 `backend/.venv/Scripts/python.exe` 并转发 `-IncludeE2E`。
- 核心逻辑可以直接由现有 pytest 覆盖，不需要引入 Pester。

不采用纯 PowerShell实现，因为当前项目没有 PowerShell 测试框架，失败分支和进程回收难以形成可靠的自动化回归。也不把命令分散到 npm 与临时批处理脚本中，以免再次出现多个入口和不同口径。

## 4. 文件边界

| 文件 | 职责 |
|---|---|
| `scripts/quality_gate.py` | 核心执行器、步骤定义、报告写入和可选 E2E 生命周期 |
| `scripts/quality_gate.ps1` | Windows 一键入口和参数转发 |
| `backend/tests/test_quality_gate.py` | 执行顺序、失败停止、报告和 E2E 生命周期测试 |
| `.gitignore` | 忽略本地 `.quality-gate/` 运行产物 |
| `README.md` | 记录默认模式与 `-IncludeE2E` 用法和证据边界 |

不修改业务服务、评测指标算法、前端页面或现有测试语义。

## 5. 默认执行流程

默认命令：

```powershell
.\scripts\quality_gate.ps1
```

执行器从仓库根目录按以下顺序运行，任一步失败即停止：

1. 评测专项：执行评测流水线相关 pytest 文件。
2. 后端全量：执行 `backend/tests` 全量 pytest。
3. 前端测试：执行 `npm.cmd test`。
4. 类型检查：执行 `npm.cmd run type-check`。
5. 生产构建：执行 `npm.cmd run build`。

默认模式主动从前端测试子进程环境中移除 `E2E_BASE_URL`，保证依赖本地服务的现有 E2E 按其测试约定跳过，不受调用者残留环境变量影响。其他前端测试仍正常执行。

评测专项虽然也包含在后端全量测试中，但保留为独立阶段，使报告可以明确区分“证据流水线契约失败”和“一般后端回归失败”。

## 6. 可选 E2E 流程

可选命令：

```powershell
.\scripts\quality_gate.ps1 -IncludeE2E
```

执行器执行以下生命周期：

1. 检查 `127.0.0.1:8000` 和 `127.0.0.1:5173` 是否可绑定；端口已被占用时直接失败，避免误用或终止用户已有服务。
2. 使用后端虚拟环境启动 `uvicorn app.main:app --host 127.0.0.1 --port 8000`。
3. 使用 `npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort` 启动 Vite。
4. 在有限超时时间内轮询后端 `/health` 和前端 `/login`；超时或子进程提前退出即失败。
5. 仅为前端测试子进程设置 `E2E_BASE_URL=http://127.0.0.1:5173`，执行完整 Playwright 测试。
6. 无论测试成功、失败、超时或用户中断，都在 `finally` 中回收脚本自身创建的前后端进程树。

执行器只记录并终止自己创建的 PID，不扫描或批量结束其他 Python、Node 或 npm 进程。

## 7. 报告与退出码

每次运行原子写入 `.quality-gate/summary.json`。报告至少包含：

```json
{
  "schema_version": 1,
  "mode": "default",
  "git_commit": "<commit SHA>",
  "started_at": "<UTC ISO-8601>",
  "finished_at": "<UTC ISO-8601>",
  "status": "passed",
  "exit_code": 0,
  "steps": [
    {
      "name": "evaluation",
      "status": "passed",
      "exit_code": 0,
      "duration_seconds": 1.0
    }
  ]
}
```

- 总状态只允许 `passed`、`failed` 或 `interrupted`。
- 未执行的后续步骤不伪造为通过；报告中不写入未执行步骤。
- 子命令输出实时转发到终端，JSON 只记录命令类别、状态、退出码和耗时，不保存完整 stdout/stderr。
- 报告目录不存在时创建，临时文件写完后再替换正式文件，避免留下半截 JSON。
- 成功返回 0；测试或构建失败返回对应非零码；启动、健康检查或内部编排错误返回统一非零码；用户中断返回 130。

## 8. 错误处理

- 后端虚拟环境 Python、`npm.cmd` 或必要项目目录缺失时，在执行任何测试前失败并给出具体路径。
- 每个步骤显示开始、结束、耗时和结果，失败信息包含阶段名和退出码。
- 默认模式不启动服务，因此不存在后台进程残留。
- E2E 模式使用有界健康检查，避免无限等待。
- 报告写入失败时门禁返回非零码，避免出现“测试通过但验收证据缺失”的假成功。
- 清理过程中不覆盖原始失败原因；进程回收异常作为附加错误写入终端并使结果保持失败。

## 9. 自动化测试策略

使用 TDD 开发，测试通过依赖注入的命令执行器、时钟、健康检查器和进程管理器验证真实编排逻辑，不运行完整项目套件来测试编排本身。

最小覆盖：

1. 默认步骤顺序固定，并从前端测试环境移除 `E2E_BASE_URL`。
2. 某一步返回非零码后，后续步骤不再执行。
3. 成功、失败和中断均生成结构完整的 JSON 报告。
4. `-IncludeE2E` 设置正确的 URL，并在成功后回收两个子进程。
5. E2E 测试失败、健康检查超时和启动异常时仍回收已创建进程。
6. 端口占用时不启动任何服务，也不终止占用端口的进程。
7. PowerShell 入口能够解析参数并调用项目虚拟环境中的 Python 执行器。

完成执行器专项测试后，再使用一键入口实际运行默认门禁，验收评测专项、后端全量、前端测试、类型检查、生产构建和最终 JSON 报告。

## 10. 完成标准

- 一条 PowerShell 命令可以运行默认质量门禁。
- 默认模式不依赖正在运行的本地服务，服务型 E2E 如实跳过。
- `-IncludeE2E` 可以启动、验证并回收本地前后端。
- 任一步失败时立即停止并返回非零退出码。
- 每次运行都生成不含敏感信息的有效 JSON 汇总。
- 执行器专项测试、后端全量、前端测试、类型检查和生产构建全部通过。
- README 明确说明自动化门禁不等于真实赛题硬指标验收。
