# RAG 证据可信度与前端运行时修复设计

日期：2026-07-31

## 1. 背景与问题

手工冒烟测试使用设备采购风险合同完成上传、解析、双 Agent 审查和风险复核后，发现以下问题：

1. “合同生效”风险同时引用劳动合同法、软件知识产权模板和《民法典》第 502 条。前两项与当前风险不匹配。
2. 历史知识的 `applicable_contract_types` 和 `applicable_dimensions` 多为空数组；检索器将空数组解释为“不限制”，导致未治理数据跨领域参与正式依据。
3. 检索结果只要进入 RRF 前列便固定标记为 `reliable=True`，可靠性没有绑定元数据完整性和检索质量。
4. 上传设备采购合同后，前端静默使用“软件开发外包合同”默认值，扩大了错误召回范围。
5. `Menu`、`Expand`、`Fold`、`ChatDotRound` 在 Vue 模板中使用但未导入，造成控制台警告和移动端空白图标。
6. 本地同步双 Agent 审查耗时约 6 分钟，缺少分阶段性能证据，不能直接判断瓶颈。

## 2. 目标与非目标

### 2.1 目标

- 未分类知识默认不得成为正式法规依据。
- 只有合同类型、审查维度、有效期和相关性均合格的知识才能标记为可靠。
- 没有可靠依据时维持现有人工复核降级：依据明确说明缺失，置信度封顶 50。
- 用户在审查前明确确认合同类型；明显的文件名/内容冲突需要提示。
- 建立跨领域误召回的负向回归测试。
- 消除四个未解析图标组件及相关控制台警告。
- 增加低成本分阶段耗时日志，为后续性能优化提供证据。

### 2.2 非目标

- 本轮不切换 pgvector，不拆分多个物理索引。
- 本轮不替换 Embedding 或 LLM 模型。
- 本轮不承诺解决外部 LLM 的绝对耗时，只完成可重复测量和安全超时边界核对。
- 本轮不批量猜测所有历史知识的业务归属；无法确定的数据保持未分类。

## 3. 方案选择

采用单索引上的显式作用域和默认拒绝策略。

未采用的方案：

- 仅提高相似度阈值：无法阻止语义相近但领域错误的劳动合同条文。
- 按合同类型拆多个物理索引：隔离更强，但迁移、导入和跨类型通用法律维护成本过高。

## 4. 数据模型

为 `knowledge_chunks` 增加 `scope_mode`：

| 值 | 含义 | 是否可进入正式检索 |
|---|---|---|
| `global` | 经过确认、适用于全部合同的通用法律或规则 | 可以 |
| `scoped` | 仅适用于指定合同类型或审查维度 | 元数据匹配时可以 |
| `unclassified` | 历史数据或无法确认适用范围的数据 | 不可以 |

约束：

- 新字段默认值为 `unclassified`，不能用默认值隐式放行旧数据。
- `scoped` 至少需要一个 `applicable_contract_types` 或 `applicable_dimensions` 值。
- `global` 只能由受控种子、受控迁移或管理员显式选择产生。
- API 和导入流程拒绝非法 `scope_mode` 组合。

迁移要求：

- Alembic 增加可回滚字段迁移。
- SQLite 启动补列同步增加该字段。
- 受控种子中的《民法典》通用条文回填为 `global`。
- 已知软件、采购、劳动合同模板回填为 `scoped` 并补合同类型/维度。
- 无法可靠分类的历史数据保持 `unclassified`。

## 5. 检索与可靠性

检索流程顺序固定为：

1. 排除 `unclassified`。
2. 对 `scoped` 执行合同类型和审查维度硬过滤。
3. 执行有效期过滤。
4. 运行 BM25 和向量检索、RRF 融合。
5. 根据来源作用域和检索信号计算 `reliable`。

可靠性规则：

- 元数据不合格的结果不进入候选集。
- `global` 和匹配后的 `scoped` 才有资格成为可靠来源。
- 向量结果仍遵守最低余弦阈值。
- BM25-only 降级必须有正向词项得分，零分文档不得进入结果。
- RRF 分数只用于排序，不能单独证明可靠。
- 内置兜底规则保留 `fallback_rule` 标识，不冒充法律条文。

没有可靠来源时：

- `rag_sources=[]`；
- `basis` 使用现有“未检索到可靠法规来源，请人工复核”口径；
- 风险置信度最大为 50；
- 风险状态保持待复核。

## 6. 合同类型确认

本轮采用保守交互，不新增 LLM 分类调用：

- 合同类型初始值改为空，不再静默选择“软件开发外包合同”。
- 未选择合同类型时禁用“启动合规审查”，并显示明确校验信息。
- 使用现有文件名和解析文本做轻量关键词建议，例如“设备/采购”建议采购合同，“软件/开发”建议软件开发合同。
- 建议只预填提示，不自动提交；用户必须确认选择。
- 后端审查接口拒绝空合同类型，避免绕过前端。

如果现有批量流程依赖默认合同类型，则批量接口继续要求显式表单字段，不从单合同页面默认值继承。

## 7. 前端运行时修复

在对应组件从 `@element-plus/icons-vue` 显式导入：

- `MainLayout.vue`：`Menu`
- `AppSidebar.vue`：`Expand`、`Fold`
- `RiskReviewDrawer.vue`：`ChatDotRound`

不采用全局自动注册，以保持依赖可追踪并减少无关图标进入构建。

## 8. 性能观测

在单合同审查链路记录结构化阶段耗时：

- `parse_ms`
- `legal_agent_ms`
- `finance_agent_ms`
- `grounding_ms`
- `persist_ms`
- `total_ms`

日志不得包含合同正文、API Key 或完整提示词。完成两次相同测试合同实测后，再决定是否并行 Agent、缩短提示词或调整模型；本轮不基于单次体验直接重构并发模型。

## 9. 测试策略

所有行为修改按红-绿-重构执行。

### 9.1 后端负向测试

- 设备采购合同生效不得召回劳动合同法。
- 设备质量保证不得召回软件知识产权模板。
- 软件源代码归属不得召回劳动合同解除条款。
- `unclassified` 文档永远不进入正式结果。
- `scoped` 缺少作用域元数据时被拒绝。
- 没有可靠来源时 `basis` 降级且置信度不超过 50。
- 空合同类型的单合同审查请求被拒绝。

### 9.2 迁移与种子测试

- 空库升级、降级均成功。
- SQLite 启动补列幂等。
- 受控通用法条为 `global`，专用模板为 `scoped`。
- 未知旧数据升级后为 `unclassified`。

### 9.3 前端测试

- 未确认合同类型时审查按钮不可用。
- 选择合同类型后可启动审查。
- 390×844 下菜单图标可见、侧栏默认隐藏且无横向溢出。
- 打开风险抽屉后 `ChatDotRound` 正常解析。
- 页面及交互后的控制台无相关 Vue component resolution 警告。

## 10. 验收标准

- 后端和前端现有全量测试零失败。
- 新增负向测试能够在旧实现上失败、在新实现上通过。
- 类型检查与生产构建退出 0。
- 浏览器验证桌面和 390×844 视口，核心页面非空、无框架错误覆盖层。
- 浏览器控制台不再出现四个图标组件解析警告。
- 手工风险样本中的“合同生效”风险不再引用劳动合同法或知识产权模板。
- Git 变更仅包含本设计范围内的源码、迁移、测试和稳定文档；不提交本地数据库、测试输出或密钥。

## 11. 风险与回滚

- 默认拒绝会减少旧演示库的可检索知识数量，这是预期的安全变化；必须先回填受控核心知识再验收演示流程。
- 如果迁移后没有可靠知识，系统必须降级到人工复核，不能恢复旧的全量放行。
- Alembic 降级删除 `scope_mode`；应用代码回滚时仍可读取原有适用类型和维度字段。
