# 提交源码赛前补强设计

日期：2026-10-08

目标：在不依赖新增硬件、外部资源或第三方依赖的前提下，补齐《契鉴》参赛源码中最影响得奖表现和真实落地的工程缺口。

## 范围与成功标准

本轮只处理四组高收益问题：

1. 生产空库可通过受控、幂等命令创建首个管理员，且不打印密码、不在生产启动时播种演示账号。
2. 单文件、单批和网关容量来自同一配置口径。后端拒绝超限批次时返回稳定错误码，前端显示同一限制，Nginx 不提前截断合法请求。
3. 风险证据明确区分候选命中、确定性验证、人工复核和最终采信。确定性验证器不可用时保守降级；任何人工确认都留下操作人、时间和理由。
4. 金额与期限抽取补足多金额、框架合同、起止日期、相对期限和跨句场景；超出 bcrypt 安全输入上限的密码被拒绝，避免截断碰撞。

完成标准：每组行为先有失败回归测试；相关后端测试、前端类型检查、前端构建和质量门禁通过；文档只写入本轮有证据支持的状态。

## 方案

### 1. 首次管理员初始化

新增 `backend/scripts/bootstrap_admin.py`，默认连接当前配置数据库，接受命令行用户名和交互式密码输入；密码只经现有 bcrypt 入口处理。脚本在生产配置下要求 PostgreSQL、强密钥和加密配置已满足，并用事务完成“检查同名—创建—审计”操作。重复运行同一用户名返回明确的已存在错误，不覆盖已有账号。

不新增无需认证的 HTTP 建号接口，不修改生产启动逻辑，不把演示账号带入生产。部署文档给出 PowerShell、容器内两种调用方式和回滚说明。

### 2. 批量容量统一

在配置中集中定义单文件上限、单批文件数和单批总字节数；导入接口、旧兼容上传接口、Nginx 模板和前端提示均引用同一口径。考虑反向代理请求体必须覆盖后端最大批次，Nginx 默认设置为单批上限加少量协议余量。

超限在进入持久化前返回 `BATCH_TOO_LARGE` 或 `FILE_TOO_LARGE`，保留现有逐文件失败隔离和追加导入能力。测试覆盖边界值、超一个字节、追加后总量超限和代理配置静态一致性。

### 3. 证据核验闭环

引入显式 `EvidenceValidationMode`：`deterministic` 使用可审计的规则验证器，`manual_only` 保持当前人工接管；默认仍以安全为先。确定性验证器只在原文已精确定位、来源可信、来源适用且风险事实有足够锚点时返回 `supported`；无矛盾识别能力时不伪造 `contradicted`，而是返回 `unclear` 并给出原因码。

审查编排显式传入验证器，持久化模式、版本、阶段、原因码和证据关系。前端和追问接口使用同一状态判定：`supported` 才能引用为已核验依据，其余状态均显示人工复核提示。该设计不把规则重叠宣传为语义模型能力。

### 4. 抽取与密码边界

在现有确定性抽取器中补充真实场景回归：合同总价与保证金并存、单价与总价并存、框架合同不设固定总额、多个日期表达、相对期限和跨段期限。只调整候选优先级和排除条件，保留原文字符区间与人工复核标记。

密码入口在哈希前拒绝超过 bcrypt 72 字节 UTF-8 上限的输入，并返回用户可理解的校验错误；不改变既有短密码兼容性。新增测试验证不同后缀长密码不会共享哈希语义。

## 文件边界

- 后端：`app/core/config.py`、`app/core/security.py`、`app/services/audit/evidence_validation.py`、`app/services/audit/auditor.py`、`app/services/parser/elements.py`、导入接口和新脚本。
- 前端与部署：`frontend/nginx.conf`、上传提示或配置接口相关组件。
- 测试：管理员初始化、导入容量、证据模式、抽取边界、密码边界的既有测试文件或新测试文件。
- 文档：`docs/deployment.md`、`README.md`、评测矩阵中仅更新可复现口径。

不修改数据库表结构、不安装 npm/Python 依赖、不接入真实模型、不修改 CI/CD、不把合成数据写成正式准确率。

## 风险与回滚

- 证据验证默认保持保守；如果确定性验证器造成误采信测试失败，立即回退为 `manual_only`，不放宽发布门槛。
- 配置统一可能影响现有大文件演示；保留追加导入并在前端提示分批上传。
- 首次管理员脚本只新增账号，不删除或覆盖账号；可通过现有管理员接口停用或人工撤销。
