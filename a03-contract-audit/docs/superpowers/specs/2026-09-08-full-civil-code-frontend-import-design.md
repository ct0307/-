# 完整《民法典》前端受控导入设计

## 目标

管理员通过法规知识库现有“导入文件”弹窗上传正式《中华人民共和国民法典》文件。系统在同一交互中完成权威法源识别、1260 条完整性校验、父子 Chunk 生成、Embedding 构建、原子替换和导入后验收。

成功后可以准确表述：开发数据库已完整收录《民法典》第 1—1260 条。合同审查仍优先召回合同编、总则和担保物权，其他各编按查询相关性参与混合检索。

## 设计原则

- 不由模型生成、补齐或改写法条；只能导入上传文件中的原文。
- 普通文件继续走现有通用导入流程，避免破坏规则、模板和案例导入。
- 权威法源导入必须先完成全部解析、校验和向量生成，再进入数据库事务。
- 同步失败时保留旧法源数据；成功时只替换同一受控法源。
- “父法条数”和“检索子切片数”分别展示，不用切片数冒充法条数。

## 识别与分流

后端从现有 `POST /knowledge/import-file` 接收文件，但在持久化前执行预检：

1. 提取 TXT、DOCX 或 PDF 文本。
2. 根据标题、正文首部及第 1 条至第 1260 条结构识别《民法典》候选文件。
3. 候选文件进入权威法源流程；其他文件继续进入现有 `_smart_split` 通用流程。
4. 权威法源流程要求条号连续、无重条、无越界条号且总数为 1260。
5. 与内置正式法源哈希一致时标记“官方基准一致”；不一致但结构完整时不自动取得权威身份，前端提示文件版本待核验并禁止覆盖受控正式法源。

第一版比赛演示使用仓库内已验证的国家法律法规数据库版本，上传该文件应通过哈希和结构双重校验。

## 接口与状态

新增两阶段接口，现有通用接口保持兼容：

- `POST /knowledge/legal-import/preview`：接收单个文件，只解析和校验，不写数据库、不生成向量。
- `POST /knowledge/legal-import/apply`：携带预检令牌并再次校验文件内容，生成全部向量后执行原子替换。

预检令牌绑定文件 SHA-256、当前用户、法源 ID 和短有效期，防止预览后更换文件。服务端不信任前端传入的法条数或哈希。

预览响应包含：

- 法源标题、正式来源和 SHA-256 校验结果
- 父法条数、预计子切片数
- 缺条、重条、越界条号
- 当前数据库同法源父法条和子切片数量
- 预计新增、替换、复用和重建向量数量
- 是否允许应用

应用响应包含：

- 实际父法条和子切片数量
- 向量模型、维度和签名
- 替换数量与保留的非受控知识数量
- 第 1、585、1260 条存在性检查
- 事务状态和审计记录 ID

## Chunk 与检索策略

每一条法条建立一个 `LegalArticle` 父记录，保存完整原文。检索子切片复用现有 `split_legal_article`：

1. 短法条保持单切片。
2. 长法条优先按自然款分割。
3. 超长款按句界分割。
4. 仍超长时按字符上限切分。

每个子切片保留 `legal_article_id`、`chunk_index`、`chunk_count`、`retrieval_text` 和 `chunk_schema_version`。Embedding 输入使用法源名称、章节标题、条号和命中片段组成的 `retrieval_text`；展示内容保持法条原文。

检索优先级：

- 明确条号查询走精确路由并返回完整父法条。
- 自然语言查询继续使用 BM25 与向量 RRF。
- 合同审查查询对总则、担保物权、合同编和合同编通则司法解释增加领域优先级，但不排除其他各编。
- 同一父法条的多个子切片只占一个 Top-K 位置。

## 前端交互

沿用现有“批量导入文件”弹窗，不新增独立页面：

1. 选择单个《民法典》文件后显示“正在校验法源”。
2. 校验完成后展示父法条数、预计子切片数、哈希状态和差异摘要。
3. 只有管理员、官方基准一致且 1260 条完整时可点击“确认导入”。
4. 导入阶段显示“生成向量”和“原子写入”状态，不展示虚构百分比。
5. 成功后展示实际结果和第 1、585、1260 条验证状态，并刷新知识库统计。
6. 缺条、重条、哈希不符、Embedding 失败或事务失败均展示具体原因；失败后原数据保持不变。

“覆盖同名旧数据”在权威法源模式下改为明确确认项，确认文案必须列出预计替换的父法条和子切片数量。普通文件仍保留现有开关语义。

## 权限与审计

- 预览和应用接口仅管理员可用。
- 审计日志记录操作者、文件名、文件哈希、法源 ID、父法条数、子切片数、向量签名和结果。
- 不把上传的临时文件、完整合同或密钥写入日志。
- 上传大小、文件类型和解析超时继续受现有安全限制。

## 测试与验收

后端自动化测试覆盖：

- 完整 1260 条预览成功且不写库。
- 缺条、重条、越界、哈希不符均拒绝覆盖。
- 预检令牌被篡改、过期或用户不匹配时拒绝应用。
- Embedding 失败和事务失败不删除旧数据。
- 重复导入幂等并复用相同签名向量。
- 普通法规、规则、模板和案例仍走原通用流程。
- 导入后父法条 1260 条，司法解释 69 条，总父法条 1329 条。

前端和浏览器验收覆盖：

- 正常预览、导入成功、缺条错误、哈希错误和服务错误。
- 桌面和移动端弹窗无溢出，长错误信息可阅读。
- 导入后搜索第 1、585、1260 条均命中完整父法条。
- “违约金约定过高”继续走混合检索并命中第 585 条或相关司法解释。

## 明确不做

- 不允许浏览器上传任意文本后标记为官方《民法典》。
- 不在前端自行计算可信法条数量或决定数据库替换范围。
- 不将 1260 条父法条和其子切片混为同一统计指标。
- 本次不证明 OpenClaw 模型在线、类脑加速性能或相对 GPU 能效比；这些需要独立实测材料。
