# 审查可靠性合并修复设计

用户已确认修复并合并至本地 master。

## 决策

- 风险 envelope 的 risks、has_more 必填。合法空结果必须明确返回两字段；缺字段沿用格式错误重试，不能保存有效检查点。协议版本升级，隔离旧校验规则的检查点。
- 任务领取统一先锁 Contract，再锁 AuditBatchItem，与校验、发布和失败处理一致。保留 generation、execution_token 和租约围栏。
- 共享瞬时数据库错误识别规则；数据库死锁、序列化冲突和锁忙按现有次数上限重试。领取前失败尚无 token 时仅重投任务，不发布失败状态。永久数据库错误不得重试。
- 领取提交成功才取得所有权；token 已生成但事务回滚仍走未领取重投。数据库文本分类只读取驱动错误，不读取 SQL 参数。开发模式隔离 eager request，使真实 Celery 重试不发送至消息队列且最多四轮。
- 仅本地合并；不推送、不删除分支或工作树，不覆盖主工作区已有未跟踪文件。

## 验收

先红后绿验证缺字段、合法空结果、分页、领取锁顺序、瞬时/永久错误分类及领取前重试。执行后端相关回归和完整质量门禁；合并后再次验证。未运行 PostgreSQL 并发实测时明确保留此限制。
