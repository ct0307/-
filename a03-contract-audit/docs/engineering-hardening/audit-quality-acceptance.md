## 角色复核与样本边界

使用两份既有合成、脱敏合同：F3-049三方框架与F3-002采购。输入重新排为原生DOCX，公开法源快照为2个来源、1329父法条、1339切片。没有发送真实业务合同或改写业务审批。

AI法务先复核旧框架两轮40项，AI财务复核其中17项财务候选，两者存在重叠。随后冻结9项法务参考问题、7项财务标签及输入/报告哈希，逐项复核新输出。新采购法务观察标记posthoc，不回填冻结标签。所有角色记录均为`ai_simulated_role`、`human_review_complete=false`，不是独立人工金标、执业律师意见或真实审批。

参考标签来自已看过旧模型输出的AI角色，存在关联性与选择偏差；正向问题、负向控制及条件待核不能混成一个召回率分母。候选数量相同也不代表内容相同。

每单实验上限300秒、24次chat、600000保守token，单请求60秒；生产默认为1500秒、120次和3000000。本轮没有扩大预算掩盖失败。各成对轮次的递归审查源码、模型、文本、公开知识、参考标签、并发与实验预算哈希一致，仅批量开关不同。原生DOCX容器哈希可能因生成时间不同而不同，正文哈希一致。

定向诊断两次复现category超过64字，system哈希与失败轮相同、user哈希不同，支持同类格式问题存在，不能声称恢复了原失败响应。最终四轮没有再次出现发现Schema失败，因此没有实际触发新增纠错重试，不能将覆盖改善直接归因该补丁。其行为通过失败回归及独立边界测试验证。

模型输出存在随机差异，实验期间还与本机质量门禁重叠。当前仅支持“批量通常减少本样本调用”的继续评估方向，不能声称稳定提速、质量不退化、代表性P95或LangGraph带来的收益。

## 输出质量复核

框架两轮均发现付款凭证与预付/出库款时序冲突，主协议相关结论改为先补材料，未将订单模板写成已实际越权，也未将责任上限、企业预算缺失强制认定为合规缺陷。

但最终框架逐条保留计税与仓配计费材料核验，批量保留超限授权核验，两者都遗漏条件性毛利测算、产品映射和价格有效期等参考线索。批量授权项未完整计算504000元与20万元限额。逐条有维度不匹配，但被拒候选内容未保存，不能猜其内容或将遗漏归因该过滤。付款问题仍在法务与财务中重复呈现。

采购两轮均正确避免“付款比例超过100%”与“30%生效预付本身违规”的误报，并发现仲裁机构/程序选择不明、三批交付与第四批备件衔接问题。两轮各有不同的补充发现，不能以11项多于10项认定更好。

采购逐条知识产权项仍用“全文未检出”，无法精确定位；批量风险4/8将分散原文拼为一条引用，组成片段可分别定位但整句未核验，状态保留。保密条款已有实质保护，剩余问题是措施覆盖范围澄清，不能写成完全没有保密义务。

采购批量风险10的128000元来自1280000元×10%，计算正确。当前事实核验只支持字面金额及明确表格行乘积，尚不支持正文总价与付款比例的结构化绑定，因此仍为`FACT_VALIDATION_FAILED`待核；候选已持久化，不是被过滤，也不能称模型编造。不得临时允许任意数字组合来绕过门禁。

所有依据仍需核验。样本缺少可确认法律基准日时，来源适用性为未知；`SOURCE_NOT_APPLICABLE`机器码不能被解释为已确认法律不适用，更不能静默补日期清除待核。

## 预算与LangGraph决策

旧采购实验中，法务4次发现+19次补充，财务用第24次完成发现，随后补充被预算拒绝。实际出站24次，持久日志25条包含一次拒绝。已用真实执行器离线复现该顺序饥饿机制。

当前采购两种方式都未重现预算耗尽，但没有实现机制上的公平保障。仅预留每角色两次或固定均分预算无法保证分页和完整补充；调用、token、截止时间和失败恢复需要一起设计。

| 优先级 | 后续工作 | 晋级判断 |
|---|---|---|
| P1 | 完善多片段原文定位、正文总价×付款比例的可追溯计算证据 | 有正反控制、唯一来源绑定，不以AI同意替代事实核验 |
| P1 | 补齐授权、毛利、计费与映射线索，检查维度路由及重复问题呈现 | 扩充冻结样本，区分必查项、条件线索和商业建议 |
| P1 | 先发现后补充的公平调度与持久化未补全候选 | 验证多角色、多窗口、预算和时限耗尽、崩溃恢复，不伪造完整覆盖 |
| P2 | 批量开关受控晋级 | 更多成对轮次覆盖失败回退及质量差异；当前生产开关保持关闭 |
| P2 | LangGraph真实A/B与正式桥接 | 先固定质量基准，再评估恢复收益；独立原型不能代表正式集成完成 |
