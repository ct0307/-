# 契鉴现场演示与验收手册

## 当前结论

本机已验证合成数据的真实上传、解析、幂等、人工类型确认、失败保护及报告导出。后端全量 1647 项测试通过，包含三组 PDF 测试。此前 PyMuPDF 原生崩溃本轮未复现，根因未明。尚未验证成功模型审查闭环，不应直接承诺现场全流程可用。

用户已确认暂时没有可用测试服务，本轮范围为本机验收和缺项清单。没有安装服务，也没有修改真实模型配置。

`rules_fallback` 当前仅禁止模型出站，主审查编排仍依赖模型输出，会出现 `INVALID_MODEL_OUTPUT` 和覆盖不完整。不能把该模式称为完整离线审查，也不能把零风险结果说成合同安全。原始模型 `.env` 未修改；未授权的外部地址会被新的出站保护阻止。

## 上场前准备

| 优先级 | 项目 | 验收标准 |
|---|---|---|
| P1 | 合法授权的模型配置 | 管理员确认地址与数据处理授权；外部地址完整匹配允许列表，或使用受控私有模型；不在 PPT 展示密钥 |
| P1 | 成功审查样本 | 使用明确标记的合成合同，实际完成上传→类型确认→审查→逐项复核→终审→导出；记录耗时与失败情况 |
| P1 | 现场设备彩排 | 用最终展示电脑和网络完整演示至少一次，同时准备失败分支 |
| P2 | PostgreSQL/Redis/Celery | 本机未提供服务；在专用测试库执行集成验收，不用生产库，不以 SQLite 结果替代 |
| P2 | 备用材料 | 准备成功流程录屏、风险原文与依据截图、已导出报告；标明录制时间、配置和合成数据来源 |
| P3 | 答辩证据 | 各项准确率、耗时、OCR 与真实合同集指标必须有对应评测记录；无记录就表述为待验证 |

## 可重复执行的本机检查

在项目根目录运行：

```powershell
# 全套单元、评测、前端测试、类型检查与构建；具体步骤以门禁实现为准。
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\quality_gate.ps1

# 隔离的真实 API 失败保护流程；不会读取项目 .env，不会访问业务数据库。
.\backend\.venv\Scripts\python.exe .\scripts\acceptance_rules_flow.py
```

隔离验收每次创建新的系统临时目录，保留合成数据库和上传件便于复核；不自动删除。通过仅代表脚本列明的失败保护检查通过，**不代表成功审查、模型或浏览器端到端通过**。DOCX/XLSX 仅校验导出容器完整性，不代表逐页视觉验收。

专用 PostgreSQL/Redis 验收入口和配置约束见 [加固说明](../engineering-hardening.md)。缺少本地 Docker、PostgreSQL、Redis，且 WSL 未安装；安装依赖或服务前应确认具体方案。

## 建议的现场讲解顺序

1. 用一句话说明：契鉴辅助企业统一合同审查流程，按法务、财务侧重点发现风险，并保留原文、依据与人工决定。
2. 上传一份合成合同，展示解析结果和类型确认；解释“解析成功不代表审查通过”。
3. 实际触发审查并显示任务状态；长时间等待时展示流程架构，不编造即时结果。
4. 选择一条真实生成的风险，依次展示合同原文、依据来源、核验状态和修改建议。没有可靠依据时明确转人工。
5. 演示人工复核意见、终审发布和报告导出，解释机器结论与人工决定分别留痕。
6. 用测量记录回答速度与准确率问题；用权限、出站授权和人工复核边界回答企业落地问题。

## 故障备用方案

| 现场情况 | 处理方式 | 对评委的准确说明 |
|---|---|---|
| 模型不可用、超时或被出站策略拒绝 | 显示真实错误，切换到预先录制的成功流程与报告 | 当前模型服务未完成响应，系统保留任务并阻止把失败结果当成审查完成 |
| 文档解析或 OCR 质量不足 | 展示质量提示，改用已验证的文本样本，保留问题件供后续处理 | 解析质量不足需人工核对，不能默认识别正确 |
| 法规引用或证据不可靠 | 展示未核验标记与人工复核入口 | 可追溯和引用校验不等于法律结论必然正确 |
| 网络中断 | 展示本机已保存的录屏和报告 | 这是预先记录的合成样本演示，不是当前实时模型调用 |

答辩避免“确保万无一失”“完全替代人工”“绝对准确”。建议表述：“系统提供可追溯的辅助审查和人工复核流程，最终结论由授权人员确认。”
