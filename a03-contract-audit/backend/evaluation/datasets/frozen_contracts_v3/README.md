# 高拟真合成冻结合同集 v3

本数据集用于合同解析、风险识别、版本关系、附件关联和批量处理验收。全部主体、地址、联系人、金额组合和业务记录均为合成测试信息，不是现实企业合同原件、法律意见或经真人律师双审的金标准。

## 数据组成

| 类型 | 数量 | 说明 |
|---|---:|---|
| 有效合同 | 50 | F3-001 至 F3-050 |
| 无效输入 | 2 | 空/损坏文件、伪装扩展名 |
| 补充失败样本 | 1 | 不计入 50+2，用于非空损坏文件重试路径 |
| DOCX | 14 | 含 4 份 OOXML 修订与批注样本 |
| 文本 PDF | 21 | 保留可检索文本层 |
| 扫描或混合 PDF | 15 | 固定扫描参数，覆盖无文本层和混合文本层 |

50 份合同覆盖采购供货、技术软件、运维咨询、租赁、建设工程、人力服务、数据与知识产权、框架订单等业务，并使用 12 种起草风格。金额既包含固定总价，也包含单价、据实结算和不设固定总额的框架交易。

## 真实性方法

- 每个案例在 `cases.py` 中显式声明交易事实，不从 v1/v2 案例派生，也不按测试断言反向生成正文。
- 正文按交易范围、价税付款、交付履行、验收质量、变更、数据与知识产权、责任救济、期限退出和治理通知等法律功能组织。
- 附件按场景和列语义生成规格、单位、批次、节点、角色、证据及补救要求，不使用“经双方确认的字段1”式占位值。
- 长合同包含项目治理、授权边界、履约台账、依赖升级和退出交接；短式订单只保留本次交易必要条款。
- 页数由内容自然排版产生，不通过重复段落、空白页或目标页数填充。
- 合同字段保持在现实条款和附件中的自然位置，不为提高当前解析器得分而集中或简化。

## 证据边界

`construction-truth.jsonl` 是构造真值，只能用于技术预评测；`gold-review-template.jsonl` 的复核人为空且状态为 `pending_human_review`。只有完成授权样本脱敏、双人独立法务复核和分歧裁决后，才可形成正式法律金标准。

静态校验通过不等于以下能力已经达标：

- 扫描件 OCR 字符准确率或字段准确率；
- 真实模型 API 的审查准确率；
- PostgreSQL、Redis/Celery 或完整 Compose 环境；
- OpenClaw/GPU 性能、功耗或能耗对比；
- 全部 DOCX 和 PDF 的人工逐页视觉验收。

当前环境无法使用 LibreOffice/soffice 批量渲染 DOCX，因此 DOCX 仅完成结构、文本、OOXML 修订和批注校验，视觉状态保持 `requires_render_review`。最终验收结果、抽样范围和残余风险见 v3 源码目录中的 `ACCEPTANCE.md`。

## 冻结规则

v3 与 v1、v2 完全隔离。生成器拒绝写入已经存在的目录；任何内容变化必须创建新的独立输出目录并重新生成清单、校验报告和视觉证据，禁止就地覆盖既有冻结输出。
